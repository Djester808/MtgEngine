# V3 — the vocabulary backlog the 200-face pilot measured

Twelve items from the pilot's unexpressible sentences. Eleven landed as records or fields in
`MtgEngine.Cards`; the twelfth was already expressible and got a worked example instead. Nothing
in `MtgEngine.Rules` or the pipeline changed, so **every addition below is inert until the arm
named against it is written**. `IrVersion` is not bumped — every addition has a default and old
card files read unchanged (`VocabularyBacklogTests.A_definition_written_before_the_additions_existed_still_reads`).

`MtgEngine.Rules` and `MtgEngine.Cards.Pipeline` still build against the new vocabulary; the
additions are all optional parameters appended to existing records or new derived records, so no
caller changed.

## Two things the coordinator should decide

1. **`ManaProduction.Restriction` / `RestrictedTo` are now duplicated** by `AddMana.SpendOnlyOn`.
   They are free text nothing reads. Retiring them is a card-file migration, so it was not done
   here; leaving both is the "two spellings of one rule" the plan forbids, so it wants a decision
   before the corpus is translated against this schema.
2. **`PlayerCant` overlaps `CantLoseGame`, `CantGainLife` and `CantWinGame`**, which are already in
   card files and already read by the engine. The flag set deliberately does **not** cover
   `CantWinGame`, and `Lose`/`LifeTotalChanges` overlap the other two. The doc comment says to keep
   using the existing three where they fit and reach for `PlayerCant` only for what they do not
   cover; if the coordinator would rather have one record, that is a migration, not an addition.

## What V3 did not reach

Everything in the brief landed. Not attempted, and not asked for: the free-text
`ManaProduction` retirement above, and a `SpellFilter` distinct from `ObjectFilter` for
`SpendOnlyOn` — `ObjectFilter(Spell: true, ...)` already says "creature spells", so a second filter
type would have been a new base with its own name table for no sentence the pilot measured.
