# P10 — what the runner now reads, and the one thing it changed outside a scenario

Measured with `dotnet run --project MtgEngine.Cards.Pipeline -- verify cards` in this worktree over
a clean `cards/`: **68 verified, 2 failed, 16 with no scenarios, 1 crashed**
(`engine:0813f37cabbabed6`), against 66 / 4 / 16 / 1 on the tip I branched from. `cards/` was

Nothing here is a request for a file I do not own. Two things the coordinator has to know anyway.

## 1. A stored generated scenario was freezing the generator — fixed in `Verify/`, but it changes `cards/`

`VerifyCommand.WithScenarios` added the smoke scenario "only when the card does not already carry
one with that id", so a card whose file already held a generated scenario ran **the copy written the
day it was first verified**, not the one the generator produces today. The first run of this wave's
generator proved it: the two Auras still reported `InZone was Graveyard` (P9's message, from P9's
scenario) and three tutors turned red with `InZone was Stack`, because their stored scenarios
predate `ScenarioSetup.AutoAnswer` and so no longer opted in.

`WithScenarios` now keeps every scenario a person or a ruling put there and regenerates the one whose
source is `GeneratedSource("smoke")`. `cards/` is generated (CARD_ENGINE_PLAN.md), so the generator
and not the file is the authority on its own scenarios.

**What this means for the merge:** the next `verify cards` on the integration branch rewrites the
generated scenario in every card file that has one — the `autoAnswer` field, the Aura's
`AttachedToIs`, the ritual's `ManaPoolIs`, the cost objects. That is a large and expected diff in
`cards/`, and it is the run that carries the statuses, so it should be committed from one run rather
than merged from several.

## 2. CR 303.4f is still the two Auras' failure, and now it says so

`AttachedToIs` reports `not attached, in Graveyard` for Song of the Dryads and Kenrith's
Transformation. That is the E3e/E1b item V5 § 3 and P9 § 3 name — the casting or zone system
carrying the spell's target onto the permanent as `AttachedTo` when an Aura resolves. Both cards
verify the moment it lands, and `ScenarioCostTests.An_aura_cast_at_a_creature_is_not_attached_yet_and_the_message_says_where_it_went`
asserts the actual message, so it turns over rather than quietly passing.
