# P17 — two-of-three agreement, a third local batch, local corpus slices (wave 15)

## What landed

1. **Two of three agree.** `AgreeStage.Agree` now takes two or three readings. More than half
   of the readings saying the same thing after canonicalisation is agreement — both of two, any
   two of three — and the file's provenance lists exactly the models that agreed. The reading
   the majority left behind is an `OutvotedReading` on the `AgreeResult` (model plus the first
   place it differs from what was agreed, or its parse error), reported in the pilot report
   under `## Outvoted readings`, and **not** kept as a candidate. Three readings of which no two
   agree are `Disputed` with all parsed readings as candidates, as before. `AgreeReport` now
   carries `AgreedByPair` and prints `agreed by pair: a+b: n, …` after the counts line.
2. **A third batch that names a subset.** `pilot-collect` takes its models from the submission's
   `batches.json`, not from `Pilot.Models`; each model's stage run covers only the cards its
   stored batch names, so a subset batch never makes the stage submit the rest to that model; a
   card named by two batches is judged on two, by three on three, by one is skipped with a log
   line. A batch the store has never heard of is recorded with the ids its own `batch.json`
   names (`FileTranslationClient.Batch`, through `PilotEnvironment.BatchOracleIds`), so `--again`
   forgets exactly those.
3. **`retranslate-submit --local --model <label>`** submits one local batch for that model and
   records it beside the submission's other batches (`Pilot.SubmitAsync(models:, merge:)`); the
   selection is unioned into `selection.json`, the prompt version is the submission's.
4. **`pilot-submit --local --next N [outDir]`** selects the next N deck faces
   (`Pilot.Next`: `Select` minus `Pilot.Done` = every id with a file under `cards/` or in any
   batch the store has recorded) and writes one local batch per `Pilot.Models` model under
   `<outDir>/local/`. **Default outDir: `.agents/slices/001`, then `002`, …** (one past the
   directories already under `.agents/slices/`). The slice's directory name scopes the batch ids
   (`local-001-claude-opus-5-001`) because the store is shared by every out directory and
   `local-claude-opus-5-001` is already the re-translation's; `SubmitAsync` refuses an id the
   store already holds rather than record it twice.

## For the coordinator: the third batch

When `.agents/retranslate/local/local-claude-fable-5-1-003/answers/` holds all 35 answers,
`.agents/retranslate/batches.json` should hold exactly:

```json
{
  "claude-opus-5": "local-claude-opus-5-001",
  "claude-sonnet-5": "local-claude-sonnet-5-002",
  "claude-fable-5-1": "local-claude-fable-5-1-003"
}
```

Then, from the repository root:

```
dotnet run --project MtgEngine.Cards.Pipeline -- pilot-collect .agents/retranslate --local
```

The collect records `local-claude-fable-5-1-003` in the store with the 35 ids from its
`batch.json`, polls it (exit 3 until every answer file exists), reads the three batches, judges
the 35 on three readings and the other 74 on two, and writes `.agents/retranslate/report.md`
with the per-pair counts and the outvoted readings. If any answer file was replaced after a
collect, add `--again`. Nothing here reaches the API. Had the batch not been written by hand,
`dotnet run --project MtgEngine.Cards.Pipeline -- retranslate-submit --local --model claude-fable-5-1 --only disputed`
would have made it and recorded the entry itself.
