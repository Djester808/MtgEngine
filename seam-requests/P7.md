# P7 — seam requests

## 1. A generated smoke scenario gives no player a library, so no card that draws can ever verify

`MtgEngine.Cards.Pipeline/Scenarios/SmokeScenario.cs` builds
`new PlayerSetup(Caster, Hand: [new CardRef(file.Name)], ManaPool: DeepPool)` — no `Library`.
`ZoneSystem.Draw` records a draw from an empty library rather than performing it (CR 121.4), so
the expectation `ZoneCount(Caster, Zone.Hand, n)` that `SmokeScenario` emits for a `Draw` is 0
whenever the card actually draws. Measured, not reasoned: `pipeline verify` over a one-card
directory whose card is an instant with `SpellAbility(Draw(Fixed(2)))` fails with
`ZoneCount was 0`. Every draw card in the corpus will fail verification for this reason, and
`Draw` is one of the four effects the smoke scenario can assert at all.

**Asked of P4 (or whoever owns `SmokeScenario`):** give each `PlayerSetup` a library — enough
cards that a draw and a draw step have something to take. See request 2 before choosing what to
fill it with.

## 2. A scenario cannot put copies of the card under test in the library and then cast it

I tried to fix request 1 from my side by topping up each empty library with copies of the card
under test before running the generated scenario. It does not work, and the reason is in the
runner rather than in the scenario:

`ScenarioRun.Place` (`MtgEngine.Rules/Scenarios/ScenarioRunner.cs`) is called for `Library`
before `Hand`, and `Name(key, id)` is first-wins (`if (!_objects.ContainsKey(key))`). So the
card's plain name resolves to a library copy, and `CastStep` — which is
`new CastSpell(..., Object(c.Card), ...)` — is refused with
`A card in that zone cannot be cast without permission. (601.3)`.

Giving every library `CardRef` an explicit `Alias` **did not** fix it: with ten aliased library
copies the cast is still refused; with none it succeeds. Evidence from the run log: objects #1–#10
are created in `Zone = Library`, #11 in `Zone = Hand`, and the `CastSpell` that follows is
refused on zone. So something other than `Name(card.Alias ?? card.Name, …)` is deciding what the
card's plain name refers to, or the alias is not reaching `Place`. Worth a look before request 1
is implemented with copies of the same card, because whoever fills the library will hit this.

I removed the top-up rather than ship a workaround; `pipeline verify` currently runs the smoke
scenario exactly as `SmokeScenario` generates it, and a card that draws is reported as failed
with the first failing expectation, which is honest.

## 3. Nothing else

The engine hash is taken here, as decided in the wave-3 table: `VerifyCommand` calls
`EventLogSerializer.EngineHash()` and passes it to `VerifyStage`. The batch implementations
endpoint C2 asked for is `POST /api/cards/implementations`; `ImplementationStatus` serialises as
the enum name through the converter `Program.cs` registers, asserted in `CardsImplementationTests`.
No `Program.cs` registration is needed for any of this — the pipeline is a console tool and the
service was registered in the wave-3 seam commit.
