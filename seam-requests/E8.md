# E8 — replacement and prevention

Three seam changes the replacement system needs. None of them blocked the wave-2 slice; each is
named with what it costs to be without it.

## 1. A prevention shield cannot be spent (CR 615.9)

`ActiveEffect` (`State/GameState.cs`) carries a `ContinuousEffect` and nothing that can change.
`PreventDamage(Amount)` is therefore a shield that never wears out: "prevent the next 3 damage"
prevents 3 of every damage event, forever, instead of 3 once.

`ReplacementSystem` cannot fix this from inside, because a shield's remaining amount is state and
the state is a fold of the log — writing `state.ActiveEffects` without an event breaks
`GameReducer.Replay`. So today a shield applies at most once per `Replace` call and is never
decremented across calls, which is right for "prevent all damage" and wrong for a finite shield.

Asked for: an event that edits one active effect, and a field for it to edit —

```csharp
public sealed record ActiveEffectChanged(int Id, ContinuousEffect Effect) : GameEvent;
```

with `ActiveEffect` gaining nothing, since the replacement writes back a
`PreventDamage` whose `Amount` is the remainder and the effect is removed when it reaches zero
(an `ActiveEffectEnded(int Id)`, or `ActiveEffectChanged` with a null effect).

## 2. A pending replacement choice cannot carry the event it is about (CR 616.1)

When two effects apply, `Replace` raises `PendingChoice { Kind = "replacement-order" }` and
returns. Resuming it means applying the chosen effect to **the event as it then stood** and
offering the result to the ones that have not applied yet. `ChoiceContext.Extra` is
`ImmutableDictionary<string, string>`, so the only thing that survives the halt is the candidate
keys, as strings. E13 cannot resume the loop from that: the proposed `GameEvent` is gone.

Asked for: the proposed event beside the question, either

```csharp
public GameEvent? PendingEvent { get; init; }   // on GameState, set and cleared by ChoiceRequested/ChoiceAnswered
```

or a `GameEvent? Event` on `ChoiceContext`. Until then the choice is raised correctly and cannot
be answered, so a board with two applicable replacements on one event stops there. Every other
path — one effect, self-replacement first, prevention — completes without a choice.

## 3. `WouldShuffle` has no event to match

`ZoneReordered(Zone, Order)` is emitted for a shuffle and for "put these back in any order"
alike, so a shuffle cannot be told from a reorder and `WouldShuffle` matches nothing. Either a
`Shuffled(PlayerId)` event beside the reorder, or a flag on `ZoneReordered`. Same shape of gap,
much smaller: no card in the deck slice needs it yet.

## Not asked for

`Stubs.Replacement` still throws; wiring `ReplacementSystem` into `Engine` is the coordinator's,
not a seam change. Its constructor is `(IQuery, ICharacteristics, IInterpreter)`.
