# E12 — seam requests: primitives the keyword expansions need

`MtgEngine.Rules/Keywords/KeywordExpander.cs` rewrites CR 702 keywords into the concrete
ability records. Five arms are written (prowess, exalted, cycling, unearth, devoid). The rest
of the expanding families stop on a missing primitive in `MtgEngine.Cards`, which E12 does not
own. Each one below is why an expansion currently emits an `Unsupported` marker instead of the
ability, so the count in the pipeline's backlog is exactly this list.

## 1. `ObjectFilter` cannot say "this object" — blocks 4 keywords

A keyword whose trigger is about the permanent it is printed on has no way to say so.
`Dies(ObjectFilter)`, `BecomesBlocked(ObjectFilter)` and `Attacks(ObjectFilter)` all take a
filter, and the filter's fields are all *descriptions* — `Other: true` says "another", but
nothing says "this one". `Self` exists as a **`Selector`**, so effects can name the source;
triggers cannot.

Blocks: **undying** (CR 702.92a), **persist** (CR 702.79a), **afflict** (CR 702.131a),
**mentor** (CR 702.135a) — and every translated card whose text begins "Whenever this
creature…", which is a large share of the deck slice, so this is not an E12-only gap.

Asked for: a `Predicate` record `IsThisObject` (sibling of `IsCopy`, `IsAttached`), or a
`bool? IsThis` field on `ObjectFilter`. A predicate is the smaller change and needs no
serializer name-table churn beyond one entry.

## 2. No "discard this card" cost — cycling is approximate

CR 702.29a: cycling is "[Cost], Discard this card: Draw a card." `Cost` has `SacrificeSelf`,
`ExileSelfCost`, `TapSelf` and `UntapSelf`, but no discard sibling. The expander currently
emits `DiscardCost(Fixed(1))`, which says "discard a card" — a player could pay it with a
different card. The test asserts only the printed cost and the draw, so it does not paper over
this; the note in `KeywordSemantics.Costs.cs` records it.

Asked for: `DiscardSelfCost` in `MtgEngine.Cards/Costs.cs` plus its name-table entry. Also
blocks **jump-start** and **madness**-adjacent readings when those get arms.

## 3. `AddTypes` has no all-creature-types flag — blocks changeling

CR 702.72a: changeling is a characteristic-defining ability making the object every creature
type, applied in layer 4. `RemoveTypes` already carries `bool AllCreatureTypes`; `AddTypes`
does not, so the only spelling available is a literal list of every creature type — which
would put card data in `MtgEngine.Rules` and break rule 1 of the plan.

Asked for: `bool AllCreatureTypes = false` on `AddTypes`, mirroring `RemoveTypes`.

## 4. `CostModifier` cannot match "this spell" — blocks affinity

CR 702.40a: affinity reduces the cost of *the spell the ability is printed on*, while it is on
the stack. `CostModifier(ObjectFilter Spells, …)` can only describe spells, and `ObjectFilter`
has no self marker (see 1), so `Spells: new ObjectFilter(Spell: true)` would reduce every
spell. Fixed by 1; noted separately because it is a casting-time reading, not a trigger, and
E3 may want to read the keyword directly instead — in which case affinity moves to
`Expands: false` beside convoke, improvise and delve, and this request is withdrawn.

## 5. Riot is a replacement, not a trigger

CR 702.136a: "this permanent enters with your choice of a +1/+1 counter or haste" is an
as-enters choice, CR 614.1c, not a trigger. The brief filed it under
`TriggeredAbilityExpansion`; the table keeps it there and its note says why, but the honest
expansion is a `ReplacementAbility` whose `With` is a `ChooseMode`. Not blocked on a missing
record — blocked on E8's replacement subsystem existing to run it. No seam change asked for;
recorded so the next reader does not re-derive it.

## Not asked for

Convoke, improvise and delve are marked `StaticExpansion` with `Expands: false` on purpose:
what they change is how the generic part of a cost is *paid*, which only `CastingSystem` can do
as it builds the payment. `TapUntappedCost` already exists for the first two. Expanding them
into a `StaticAbility` would give one rule two writers.
