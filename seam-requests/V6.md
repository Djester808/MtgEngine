# V6 — the vocabulary for what the pilot could not say, and who has to read it

Six additions, every one of them an optional member or a new record, so `IrVersion` is unchanged and
every card and scenario file written before this wave reads unaltered. **None of them does anything
until the folder named below reads it.** Until then a card carrying one round-trips, lints clean and
is ignored, which is the honest state and not a silent failure — but it is also not `Verified`.

Five items on the brief's list are **not** added, because the vocabulary already says them. Those are
in "Already said" at the end, with the record that says each; a second spelling of any of them costs
translator agreement, which is the whole reason the list exists.
`VocabularyAdditionsWave8Tests.The_shapes_the_pilot_reported_missing_that_already_existed_have_no_second_spelling`
asserts the absent records stay absent, so a later pass cannot quietly add one back.

## 1. `MayPay` — owed by `MtgEngine.Rules/Interpreter` (E9-series)

```csharp
public sealed record MayPay(Cost Paid, Effect Then, Effect? Else = null, PlayerRef? Who = null) : Effect;
```

CR 118.12: "[A player] may [do something]. If [that player] [does, doesn't, or can't], [effect]. The
action [do something] is a cost, paid when the spell or ability resolves."

**The arm owed**: ask `Who` (defaulting to the resolving controller) whether they pay; on yes, run
`Paid` through the same cost payment the activation path uses, and on a payment that completes run
`Then`; on no, or on a cost that cannot be paid, run `Else` if it is there. CR 118.12's last sentence
is the part that is easy to get wrong: the "if you do" clause **checks whether the player chose to
pay, not what events actually occurred** — a sacrifice whose creature was already gone still counts
as paid once the player started paying it.

It is the mirror of `Unless`, whose arm already exists, and CR 118.12a is the identity between them:
"[do something] unless [a player does something else]" means "[a player] may [do something else]. If
[that player] doesn't, [do something]". The two must not be collapsed into one another in the
interpreter either — which half the card prints is the half the card file keeps.

**Owed by the canonicaliser (P-series)**: the pilot's translations spell this as
`May(PayCost(...), StoreChoiceAs: k)` followed by `If(ChoiceIs(k, "yes"), ...)`. That is four records
where there is now one, and it is exactly the "translator structure" disagreement the wave-5
coordinator note counted. A canonical pass should collapse that shape into `MayPay`. `PayCost`'s doc
comment now says so and points at this record; `PayCost` stays for a cost a card makes a player pay
outright with no choice and nothing hanging on it.

**Linted** (`L014`, `Linter.CheckPayments`): a `MayPay` offering a `LoyaltyCost` is an error
(CR 606.2 — a loyalty cost is an activation cost of a loyalty ability, so nothing can pay one on
resolution); a `Paid` that asks for nothing (an empty `Costs`, an empty `ChooseCost`, a blank
`ManaCost`) is an error, because a choice nobody would decline is a dropped half of the printed text;
a `Then` of `DoNothing` with no `Else` is a warning.

## 2. `TappedForMana` — owed by `MtgEngine.Rules` triggers and the mana subsystem

```csharp
public sealed record TappedForMana(ObjectFilter What, Color? OfColor = null, string? OfChosenColorKey = null) : Trigger;
```

CR 106.12a: "An ability that triggers whenever a permanent 'is tapped for mana' or is tapped for mana
of a specified type triggers whenever such a mana ability resolves and produces mana or the specified
type of mana", where "tap for mana" is CR 106.12 — activating a mana ability whose cost includes {T}.

**The arm owed**: the trigger fires on the **mana ability resolving and producing**, not on the
permanent becoming tapped, so `BecomesTapped` is the wrong event and a `ManaChanged` fold is the
right one; it needs the source permanent and the mana produced on the event. `OfChosenColorKey` reads
the colour out of the `ChooseValue(ChooseWhat.Color, key)` the same card stored, the way
`Devotion.ChosenColorKey` and `IsChosenColor` already do — the query arm for those is the arm for
this.

The other half of "whenever a land you control is tapped for mana of the chosen color, add an
additional one mana of that color" was already there: `ManaProduction.ChosenColorKey` (V3). Nothing
new is owed for it beyond the evaluator arm wave 5 already listed.

**Linted** (`L015`): `OfColor` and `OfChosenColorKey` both set is an error — a card prints one colour
restriction, and the fixed colour and the chosen one are different cards.

## 3. `ManaSpent` and `AddMana.Key` — owed by the mana subsystem and the casting system

```csharp
public sealed record ManaSpent(string ManaKey, ObjectFilter? OnSpell = null) : Trigger;
public sealed record AddMana(..., string? Key = null) : Effect;
```

CR 106.6: a mana instruction may "create a delayed triggered ability (see rule 603.7a) that triggers
when that mana is spent". CR 106.6a: if a replacement effect increases the mana produced, **a
separate delayed ability is created for each mana produced**.

**The arm owed**, and it is two pieces:

- **The mana pool has to remember where each mana came from.** `ManaPool.Restricted` (wave 6) already
  carries a per-mana block for `AddMana.SpendOnlyOn`; this key rides beside it on the same mana.
  Mana is not an object, so there is nothing else to point at and no `Remembered` selector can hold
  it — that is why the channel is a string key rather than a selector.
- **`ManaSymbols.Pay` has to report which mana paid** (E3e already owes the restricted-block half of
  exactly this), so the casting system can fire the delayed abilities keyed to the mana that was
  spent, filtered by `OnSpell` where the card names one.

`ManaSpent` is meant to be the `When` of a `DelayedTrigger` the same resolution creates, never a
printed `TriggeredAbility`'s own trigger: the mana it watches does not exist until the `AddMana` has
run.

**Deliberately not linted.** A `ManaSpent` whose key no `AddMana` in the same ability produced is not
a lint error: the mana can be produced by a linked ability on another face or another permanent
(CR 106.6), so the key is resolved where the mana is. The comment in `Linter.CheckPayments` says so,
to stop a later pass adding the check.

## 4. `CreatedTokenThisTurn` — owed by the query, off `TurnHistory`

```csharp
public sealed record CreatedTokenThisTurn(PlayerRef Who, ObjectFilter? What = null) : Condition;
```

CR 111.1. The state is nearly there: `TokenCreated` is already a trigger, and wave 6 taught
`TurnHistory` to keep the departed `GameObject` for `Died`/`LeftBattlefield` rather than only ids. A
**`TokensCreatedThisTurn` list keyed by the creating player, keeping the token object** is the same
shape and the same reason — `What` is read against the token as it was created, so a Treasure that
has since been sacrificed still answers, exactly as `AttackedThisTurn` counts a creature that has
died. Without the object the condition can only be unqualified, which is the defect E0b wrote up for
morbid and revolt.

## 5. `ObjectFilter.HasBasicLandType` — owed by the query's filter matcher

CR 205.3i names the five basic land types. True when the object has any of Forest, Island, Mountain,
Plains or Swamp among its subtypes, whatever else it has. It cannot be spelled with the fields that
were already there: `Supertype.Basic` is a different question (a dual land has a basic land type and
is not basic), and `Subtypes` is joined with "and", so it cannot say "any of the five".

**The arm owed**: one clause in the filter matcher, reading the subtypes after layer 4 so a land that
has been given a type answers yes.

## 6. `ActivatedAbility.PayOnlyFrom` — owed by casting / `CostPayment`

```csharp
public sealed record ActivatedAbility(..., Color? PayOnlyWith = null, ObjectFilter? PayOnlyFrom = null) : Ability;
```

The brief asked whether `PayOnlyWith` already covers the two pilot reasons "Cannot express a
restriction on which mana may be spent to activate an ability". **It does not, and the field's own doc
comment said so before this wave**: "A restriction that names a source rather than a colour — 'mana
produced by artifacts' — is not this field; it goes to a primitive request". This is that request.
`PayOnlyWith` is a colour; `PayOnlyFrom` is the permanent whose mana ability produced the mana
(CR 106.6b, the spend restriction's other half).

**The arm owed**: the same per-mana provenance §3 asks the pool for. Once a mana knows the permanent
that made it, `PayOnlyFrom` is a filter match at payment time and `ManaSpent` is a trigger at spend
time — one seam, two readers. Until it lands, an ability carrying `PayOnlyFrom` is payable with any
mana, which is a **different card**; a `Refused` at activation would be more honest than a wrong
payment, and the casting builder should choose which.

**Linted** (`L016`): both `PayOnlyWith` and `PayOnlyFrom` set is an error (a card prints one
restriction, and two read as an "and" no card asked for); a `PayOnlyFrom` whose filter is empty is an
error, because a restriction that restricts nothing is a translation slip.

## Already said — five items on the list that are not added

| Asked for | Already spelled as | Where |
|---|---|---|
| `PayGenericMana(Amount)` cost | `PayManaCost(Amount Generic, string? Colored)` — its doc comment's own example is "unless that player pays {X}, where X is this creature's power" | `Costs.cs`, V3 |
| `AttackedWithCount(Amount AtLeast)` | `AttackedThisTurn(PlayerRef Who, Amount Min)` — already the numbered form, with `Raid` kept only because the ability word is printed | `Conditions.cs` |
| `ObjectFilter.AttackingOrBlocking` | `ObjectFilter.InCombat`, added for exactly this disjunction (CR 506.2, 506.4) | `Selectors.cs` |
| `Search` across more than one zone | `Search.Zones` (`IReadOnlyList<Zone>?`) beside `From`, with the CR 701.23c shuffle rule already written into the doc comment | `Effects.Actions.cs` |
| `Devotion` to a chosen colour | `Devotion.ChosenColorKey` | `Amounts.cs`, V3 |

`LifeTotalCantChange(PlayerRef)` is **also not added**, and this one is a decision rather than an
oversight. "Your life total can't change" is already `PlayerCant` with
`PlayerRestriction.LifeTotalChanges`, which is how wave 5 decided it
("Keep the three specific records as the spelling for those three restrictions; `PlayerCant` stays
for the rest"). Adding a sixth specific record would reopen that. What is owed is the **layers/SBA arm
for `PlayerCant`**, which wave 5 already listed and which is still not written.

## Not asked for, recorded for wave 9 instead

- **A colour-set reference — "protection from each color not in your commander's color identity".**
  The vocabulary has no computed colour-set type at all: `Color` is a flag enum for printed colours,
  `ProducesMana(Color)` and `Adamant(Color)` take fixed ones, and `ManaProduction.CommanderIdentity`
  is a *mana* instruction, not a reference a `Protection` keyword's `Of` filter can read. Adding one
  is not a small record: it needs a `ColorSetRef` abstract base with at least `FixedColors`,
  `CommanderIdentityOf(PlayerRef)`, `ChosenColor(key)` and `Complement(of)`, and then every field
  that today takes a `Color` has to decide whether it accepts one. **That is a decision point for the
  coordinator, not a builder's call**, because it changes the shape of existing fields and so is the
  first thing in this programme that would move `IrVersion`. One pilot card wants it. Recommendation:
  leave it `Unsupported` until a second card does.
- **`MayPlayFromZone.WithoutPayingManaCost`** (E9f's "Not asked for" item, listed for V6 in the
  wave-7 table). Not added this box — it is a one-flag change but it is only honest alongside E3f's
  `CastPlan.For` reading `MayPlayFromZone` at all, which is wave 8's own work and not landed as this
  is written. Add the flag in the same landing as the reader, so the permission and the cost it
  carries arrive together; foretell, suspend and "cast it later" all want it.
- **Cost objects on a may-cast question** (E9f §2). Unchanged by anything here: it is a casting seam,
  and `MayCast` needs no new member for it.
