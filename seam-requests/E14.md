# E14 — views and legal actions

Nothing here blocked the landing; both requests are seams the coordinator asked to be named
rather than edited.

## 1. `ICombatSystem` has no attacker-eligibility check (asked for by the brief)

`LegalActions.EligibleAttackers` needs to know which creatures could be declared as attackers.
`CombatSystem` already answers exactly that question in `CouldAttack(GameState, ObjectId,
Characteristics)`, but it is private, so `Legal/LegalActions.cs` re-reads CR 508.1a, 302.6,
702.10b and 702.3b for itself. Two readings of one rule is the drift the plan forbids: an
attack restriction E4 adds later ("can't attack unless ...", CR 508.1d, which `CouldAttack`
already consults through `IQuery`) will be enforced on the declaration and still be offered by
the view.

The check I would rather call:

```csharp
[RuleRef("508.1a")]
public interface ICombatSystem : ISubsystem
{
    /// <summary>Whether this creature could be declared as an attacker now, ignoring whom it would attack, CR 508.1a.</summary>
    bool CouldAttack(GameState state, ObjectId creature);

    /// <summary>Whether this creature could be declared as a blocker now, ignoring which attacker it would block, CR 509.1a.</summary>
    bool CouldBlock(GameState state, ObjectId creature);
}
```

`CombatSystem` already has the body of the first; `LegalActions` would take `ICombatSystem`
in its constructor and keep only the step, the active player and "is this player defending"
(CR 506.2), which are the view's questions rather than combat's. Until then my reading stands
and is tested at `LegalActionsTests.An_attacker_must_be_untapped_and_controlled_since_the_turn_began`
and `.Haste_lets_a_creature_that_entered_this_turn_attack`.

## 2. Wiring — `Subsystems.Wave1()` still composes `Stubs.Views` and `Stubs.Legal`

`Engine/Game.cs` is the coordinator's. The two replacements are:

```csharp
new Views.ViewProjector(layers, oracleId => store.ByOracleId(oracleId) is not null)
new Legal.LegalActions(casting, layers)
```

`ViewProjector` takes the enforcement lookup as `Func<string, bool>` rather than the store, so
`MtgEngine.Rules` still knows nothing about card files: the API passes the deck gate's
`StatusOf`, and a game composed for a test passes whatever it likes. `Game` holds the
`IDefinitionStore` it was created with, so the wiring above needs nothing new on the seam.

## Not requested, deliberately

- **Supertypes on `ObjectView`.** A client rendering "Legendary Creature — Beast" needs them
  and the view has nowhere to put them. I own the record and could have extended it, but every
  field added to a view is a field someone has to decide is public, and no wave-2 consumer
  reads it yet. Ask for it with the board, and it is one line.
- **The pending choice for other viewers.** A choice that is not the viewer's is projected with
  its id, its player, its kind and its min/max, and with the prompt, the options and the
  context emptied — an option can name a card only its own player may see (CR 101.4). The
  alternative, dropping it entirely, leaves a client unable to say whom the game is waiting on.
