# P16 — smoke scenarios for the ten cards the generator could not stage

Wave 15. Five of the ten verify now (Lightning Bolt, Regrowth, Bala Ged Recovery, Exsanguinate,
Return of the Wildspeaker); four wait on two seams below; one stays without a scenario on purpose.
Generator side: `MtgEngine.Cards.Pipeline/Scenarios/**`, tests in
`tests/MtgEngine.Pipeline.Tests/ScenarioStageTests.Roads.cs` (each played through
`Subsystems.Wave2()`).

## 1. `ScenarioFiller` needs a basic land per basic land type (three cards)

`1b882a0e-0ede-4d1a-bd1a-9b7cffbcde8e`, `78826359-fe63-44ad-adc4-a17ffcd710e4`,
`376c9d3f-21d3-4251-bb6a-026fa9e1b0e1` all say `Search { For: { Subtypes: ["Forest"] }, To: Battlefield }`
(the third "up to two"). No filler carries a subtype, and inventing one on the pipeline side is
inventing a card — the runner resolves names through `ScenarioFiller.For`
(`MtgEngine.Rules/Scenarios/ScenarioRunner.cs:334`), which is E-series.

Ask, in `MtgEngine.Rules/Scenarios/ScenarioFiller.cs`: five basic lands, one per basic land type
(CR 305.6), e.g. `public const string Forest = "Scenario Filler Forest"` with
`new TypeLine(CardType.Land, Supertype.Basic, ["Forest"])`, each added to `For` **and to `Names`**.
Nothing else: the intrinsic mana ability is CR 305.6 data the engine already generates, and a
smoke scenario asserts only the zone.

The generator is ready for it: `SmokeFillers.Cards()` now appends every name in
`ScenarioFiller.Names` its plain list does not spell, behind the plain ones, and `Matches` reads
`Subtypes` any-of and `NotSubtypes` against the filler's printed type line (CR 205.3). With the five
lands in, the three cards stock a Forest on top of the library and expect `InZone(find-1,
Battlefield)` plus `Shuffled(A)` — the same road the "two basics" search already verifies through
(`ScenarioStageTestsSearches`). No pipeline change is needed when it lands; a test in
`ScenarioStageTestsRoads` may then add a Forest search beside the non-Human one.

## 2. An unkeyed `Target` reads every announced target, not its own slot (one card)

`37a55560-6e32-4f54-b9a8-fd157aea6eb5` (front face) is `Fight { A: Target { creature you control },
B: Target { creature you don't control } }`, neither keyed. `MtgEngine.Rules/Query/Query.Selectors.cs:25`
resolves a `Target` without a `Key` to `context.Targets` — the whole announced list — so
`EffectInterpreter.Backlog.cs:349` takes `attackers[0]` and `defenders[0]` from the same list and
the first creature fights itself. Reproduced by playing the generated scenario through
`Subsystems.Wave2()`: with a 6/6 aimed as A and a 2/2 as B, the 6/6 ended in the graveyard and the
2/2 stood. `EffectWalk.TargetsIn`'s own doc says the slot a chosen target fills is the slot the
tree named (CR 601.2c, 608.2b re-check), and the keyed road already does that: the wave-13 join
remembers every keyed `Target` as announced, and the same scenario with `Key: "a"` / `Key: "b"`
plays correctly (`A_fight_names_both_creatures_and_expects_the_smaller_one_dead`).

Ask: an unkeyed `Target` / `AnyTarget` selector reads the objects announced for its own slot, in
`EffectWalk.TargetsIn` order — the interpreter remembering unkeyed selectors under their slot
index as it does keyed ones under their key would do it, with no vocabulary change. When it lands:
drop `Key: not null` from the `Fight` arm in `SmokeScenario.cs` and delete
`A_fight_between_unkeyed_targets_gets_no_scenario_until_the_engine_fills_slots`; the card then
gets its scenario (the generated one is what the rules say — the loser in its owner's graveyard,
the winner on the battlefield, CR 701.14a with 704.5g). Until then the card stays "no scenarios"
rather than "failed", so the count does not report the engine's gap as the card's.

## 3. Changing a spell's target — left without a scenario, on purpose

`c20a96f7-aa5a-4c15-b8b1-806685c99b27` is `ChangeTarget { What: Target { In: Stack } }`. The only
filler spell (`ScenarioFiller.Spell`) targets nothing, so nothing the board can put on the stack has
a target to change; a scenario that always passed would be worse than none (`SmokeScenario.cs`'s
rule). If wanted later: a filler instant that deals 1 damage to target creature, plus a second legal
creature, and a road that casts it at one, changes the target to the other and expects the damage
marked on the second (CR 115.7). Not asked for now.

## Notes, not seams

- `8164b1e8-3350-465e-8a17-75f57d326344`: the scenario asserts the opponent's half only
  (`Life(B, 20 - X)`, X announced as 1). The caster's gain is `GainLife { N: Stored k1 }` behind a
  `Store` / `ForEachPlayer` / `Sum`, and the generator does not evaluate stored arithmetic — that
  would be asserting the generator's sum, not the card's. The brief's `Life(A, 20 + X)` is left out.
- `Draw { N: X }`, `GainLife { N: X }` and `DealDamage { N: X }` now read the announced X the way
  `LoseLife` does (one `Number` helper, CR 601.2b); a card with no `{X}` in its cost asserts nothing.
- `SmokeScenario.cs` was over 500 lines; `Costs`/`Enchant` moved to `SmokeScenario.Costs.cs` and
  `Stock`/`Found` to `SmokeScenario.Searches.cs`, unchanged.
