## 1. **Ask (E-series):** "each player sacrifices" from a triggered ability only takes the caster's

`d8ad23a1` (Accursed Marauder) is a creature whose arrival trigger is
`Sacrifice { What: null, Choice: { Types: Creature, Token: false }, Who: EachPlayer }`. With a body
older than the card under test standing on **both** battlefields, the play run through the real
runner puts the **caster's** body in the graveyard and leaves the **opponent's** on the battlefield:
asserting both halves fails with `InZone was Battlefield`, asserting only the caster's half verifies
1/1 (proved by running it both ways — the two verify runs are in this box).

So `EachPlayer` on a triggered ability's `Sacrifice` reaches one player, not every player
(CR 701.16 with CR 102.1: "each player" is every player in the game, in APNAP order). Whether the
opponent is never asked or is asked and never answered is the engine's to say; the generator can
only report that their permanent does not move.

Owner: `MtgEngine.Rules` (the interpreter's `Sacrifice` arm for `EachPlayer`, and whatever answers
its choice for a player who is not the one resolving). Until it lands the arrival road asserts the
caster's half only — a real assertion, not a vacuous one, but **half of what the record says** — and
`SmokeScenario.Enters.Edicts` carries the divergence in its doc comment. The spell-side arm
(`case Sacrifice { Who: EachPlayer }` → `Sweep`) asserts both battlefields empty; if that road has a
verified card behind it, the two disagree and the trigger path is the broken one.

## 2. **Ask (R-series, `MtgEngine.Rules/Scenarios/ScenarioFiller.cs`):** one creature per colour

`9d73a51a` (Brave the Elements) is `Apply { What: GrantKeyword Protection, To: Each { Types: Creature,
ControlledBy: You, Colors: White } }`. The fillers hold exactly one coloured body,
`ScenarioFiller.GreenCreature` (CR 202.2), so a filter naming any other colour describes a permanent
the board cannot stand. Wave 24 stood the colourless `ScenarioFiller.Creature` for it regardless,
which is why the card failed with "EventLogged was never logged": a continuous effect over an empty
set is never created at all (CR 611.2c), so the event the scenario asserted could not be logged.

Fixed honestly this box — the arm now stands the body the filter actually describes and refuses when
there is none — so the card is **no scenario** rather than a failure. Four more coloured fillers
(a white, a blue, a black and a red 1/1, printed exactly as `GreenCreature` is, colour indicator and
all) would turn every "creatures of a colour you control" card into a play. Owner:
`MtgEngine.Rules/Scenarios` (R-series); one line each, and `SmokeFillers` reads them off
`ScenarioFiller.Names` with no pipeline change at all.

## 3. Natural Order `8c1fe337` — the brief's first item was already done

The brief asked for `ScenarioFiller.GreenCreature` in `SmokeFillers.Cards()`. It is **already
offered**: `Cards()` returns the plain list and then `[.. ScenarioFiller.Names.Where(not in plain)]`,
and `Names` has carried `GreenCreature` since it was added to the fillers. Adding it to the plain
list would move it from behind the basic lands to in front of them and change no result (no filter
admits both a green creature and a basic land), so nothing was changed and nothing was re-run for it.

The card still gets **no scenario**, and the reason is not the filler: `Search { For: { Types:
Creature, Colors: Green }, To: Battlefield }` is refused further up. That is a search-destination
reading, not a filler gap — `SmokeFillers.Findable` answers this filter with `GreenCreature` today.
The next P-series box should put a breakpoint in `SmokeScenario.Searches.Stock`/`Found` rather than
in the fillers; this box ran out of time before it could.
