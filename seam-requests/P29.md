# P29 — slice 010's three new failures, and the fourteen without a spell ability

Wave 30. Owns `MtgEngine.Cards.Pipeline/Scenarios/**`, `Verify/**`,
`tests/MtgEngine.Pipeline.Tests/ScenarioStageTests*.cs`, `VerifyCommandTests*.cs`.
Anchor `ScenarioStageTests`.

## 1. The three new failures — measured at the wave-30 base (`0aded73`, engine `0f74a03de66e7d38`)

Each was run on its own with `verify cards --only <full oracle id>` (the flag matches the whole id,
not a prefix — a short id prints "nothing to verify in cards", which is worth knowing before the
next box loses a call to it).

### Plaguecrafter `2e3ee458` — the harness's, and fixed here

`InZone was Graveyard`: the expectation is `InZone(Plaguecrafter, Battlefield)` and the card was in
a graveyard. **The scenario stocked nothing at all** — both battlefields empty — and the card's own
arrival trigger then ate it, because the caster's only creature was the one that had just arrived.

The board has an arm for exactly this (`SmokeScenario.Enters.Edicts`), and it did not fire: it reads
`Sacrifice { Who: EachPlayer }`, and Plaguecrafter's record is
`ForEachPlayer { Over: EachPlayer, Do: If { Test: Controls(TriggeringPlayer, …), Then: Sacrifice { Who: TriggeringPlayer }, Else: Discard } }`
— the each-ness has moved off the sacrifice and onto a wrapper, with the "each player who can't"
half as the else-branch. `Flatten` only descends a `Sequence`, so nothing downstream ever saw the
`Sacrifice`.

**Fixed** in `SmokeScenario.Enters.cs` as `EachIsAsked`: a `ForEachPlayer` over `EachPlayer` whose
body is a `Sacrifice` or an `If` whose then-branch is one stands a body the filter admits on **both**
battlefields, older than the card under test (CR 400.7), and expects the caster's in its graveyard.
The `If` is deliberately not evaluated — standing the body on both sides is what makes
`Controls(TriggeringPlayer, …) ≥ 1` true for every player, so the then-branch is the branch each
player takes and the else-branch cannot run. Three tests in `ScenarioStageTests.Wave30.cs`: the
staged board, a falsifier that the bodies are the filter's kind and not the card's, and a filter
naming a controller standing nothing on either battlefield and writing no graveyard count — the
cast still asserts the arrival, and what the arm must not do is half-stage the trigger.

**Measured on the card**: `verify cards --only 2e3ee458-…` now reports
`verified Plaguecrafter 1/1` (run `verify-20260908T092042-d92ad1`, 0 stale).

### Karoo `d4e875d9` — the harness's, not fixed (the next P-series item)

`InZone was Graveyard`, 1/2: the land's own trigger is
`Unless { Do: Sacrifice { What: Self }, Paid: ReturnToHandCost { What: { Subtypes: [Plains], Tapped: false } }, Who: You }`
and the board stood no Plains, so the only thing the caster could do was fail to pay and sacrifice
the land. Same shape of defect as Plaguecrafter's: the board asserted an arrival the card's own
trigger undoes. (The second scenario, the `{T}: Add {C}{W}` activation, passes.)

`Enters` has no `Unless` arm. Writing one is `Scenarios/**` and therefore a later P-series box's, but
two things have to move with it and only the first is in that folder:

- `SmokeFillers.Plain` does not list `ObjectFilter.Tapped`, so **any** filter carrying `Tapped:
  false` fails `Plain` and `Bodies` returns nothing. An untapped body is the ordinary state of one
  the setup stands, so admitting `Tapped: false` (and refusing `Tapped: true`, which the setup would
  have to tap) is the honest reading. `SmokeFillers.cs` is mine; it is not changed here because the
  arm that would use it is not written.
- Whether the runner's first-legal answer **pays** an `Unless` cost or declines it is not something
  a generator can assume. If it declines, no board can stage this card and the arm should not be
  written at all. That is one question to `Agree/**`/the scenario runner before the arm.

### Frantic Search `16e015b2` — not the harness's; an engine ask (E-series, `Interpreter/**`)

`InZone was Stack`: the spell never left the stack, so its resolution did not finish. The board is
honest — caster hand is the card plus three filler lands, library eight, both battlefields empty,
deep pool; the record is `Sequence [ Draw 2, Discard { N: 2, By: Owner, WholeHand: false }, Untap
{ What: Choose { Filter: Land, Count: 3, UpTo: true } } ]`, and the expectations are the graveyard,
`Library 6`, `Graveyard 3`, `StackEmpty`. Nothing there asserts the wrong zone and nothing is
missing from the setup: "up to three" permits zero, and the discard has four cards to take from.

**The `Untap` is not the staller.** `EffectInterpreter.Choose.cs:54` recalls an empty answer when
there are no candidates, so an "up to" over an empty battlefield does not ask a question. That
leaves the `Draw` or the `Discard`, and the discard of **two** is the lead: the wave-29 reader rule
("a zoneless discard filter defaults to the battlefield, so `Discard` forces `In = Hand`") was
recorded for a discard of one, and a plural discard is the case it was not measured on.

**This is a lead and not a verdict** — I did not read the run's events. The verify path prints no
event log (`VerifyCommand` keeps only the failed expectation), and printing one would have wanted a
scratch harness this box had no room for. What the next box needs is the event list for that one
scenario; the rest of the diagnosis above is measured.

Reported as an ask so it is not lost: **the halt itself belongs to `Interpreter/**` (E3-series)** if
the discard is confirmed, and to `Scenarios/**` only if the events show the board stocked something
the resolution could not use — which, on the setup above, I do not believe.

## 3. Not done in this box

- **P28 § 3's reason for the fourteen does not survive a test, and the next box should re-measure
  before working from it.** The row says `SmokeBoard.Empty` refuses a permanent whose only content
  is its arrival. It does not: `SmokeScenario.Of` writes `InZone(card, Battlefield)` (or
  `AttachedToIs`) for every permanent *before* `Enters` runs, so `_expect` is already non-empty and
  `Empty` is false — the third wave-30 test pins exactly that, a permanent whose trigger no arm
  stages still getting a scenario. Whatever refuses those fourteen is upstream of the `Empty` check
  (`CastIsExpressible`, `Costs` or `Enchant` are the candidates) and was not identified here.
- **The fourteen without a `SpellAbility` (P28 § 3, largest group).** Not staged. One of them —
  Karoo — turned out to be one of the three new failures rather than a missing scenario, and its
  diagnosis (§ 1) is the shape the rest of that group wants: an arm for the *one* thing the
  permanent's own trigger or static does that a board can make happen and count. The group's other
  blocker is the same `SmokeFillers.Plain` gap wherever a filter carries `Tapped`.
- **The later groups** (the `Move` of an `Each`, the `Counter` refusal arm, `DealDamage` off a
  stocked count) — untouched; P28 § 3's order stands.
- **A wrong CR citation in a file I own, left alone.** `SmokeScenario.Enters.cs` carries
  `[RuleRef("701.16")]` on `Edicts` and `Sacrifices` and cites CR 701.16a in their comments. CR
  701.16 is **Investigate** and CR 701.16a is "'Investigate' means 'Create a Clue token.'";
  **Sacrifice is CR 701.21**. The new arm cites 701.21 correctly. The two existing attributes are
  not changed here because a `RuleRef` is read by the gate's own checks and re-pointing them is a
  change worth its own measurement rather than a drive-by at the end of a box.
- **Nothing outside my own files is committed.** The per-card verify runs rewrote
  `cards/16e015b2-…json`, `cards/2e3ee458-…json`, `cards/d4e875d9-…json` and their `.lint` siblings;
  they are left unstaged.
