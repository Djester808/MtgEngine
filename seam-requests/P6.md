# P6 — seam requests

## 1. The pilot's report should be `AgreeReport.Of`, not a hand-grouped list

`AgreeStage.Agree` now returns first differences that have already been canonicalised, and
`Agree/AgreeReport.cs` groups a batch of `AgreeResult`s by the property that differed, largest
first, with an example per group and a `Text()` rendering. The pilot script and `pilot-collect`
are the coordinator's files, so I have not wired them. One line where the pilot prints its
summary:

```csharp
Console.Write(AgreeReport.Of(results).Text());
```

That is what turns the next round's decision into a data question instead of thirty-seven
sentences read once.

## 2. "Any target" has no spelling in the vocabulary

`DealDamage` carries `To` (a selector) and `ToPlayer` (a player ref) separately, and nothing
names the triple Creature/Planeswalker/Battle-plus-players. So one model writes
`anyTypes: ["Battle","Creature","Planeswalker"]` on the filter and the other omits it, and the
two readings are not equivalent — an absent `anyTypes` matches lands as well. Canonical leaves
both exactly as written and the card stays `Disputed`; `Any_target_is_left_as_written_because_the_vocabulary_has_no_spelling_for_it`
records that decision.

If it is worth closing, the cheap fix is a vocabulary change, not a canonicalisation rule: an
`AnyTarget` selector (or a `bool AnyTarget` on `DealDamage`) that means CR 115.4's "any target",
plus the interpreter arm and the name-table entry. That is a `MtgEngine.Cards` change and so
outside my files. Until then the translator reference should say which of the two spellings to
use; I have not added it to the "One spelling" section because neither is more canonical than
the other today.
