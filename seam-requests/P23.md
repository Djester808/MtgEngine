# P23 — the retarget lands, and the twenty-four cards without a scenario, one verdict each

Wave 24. Generator side is `MtgEngine.Cards.Pipeline/Scenarios/**`; the tests are
`tests/MtgEngine.Pipeline.Tests/ScenarioStageTests.Wave24.cs` and the withheld retarget test in
`.Roads.cs`, each road played through `Subsystems.Wave2()`. **One engine ask**, § 2.

Reading `cards/` for a Translated or Verified file with an empty `scenarioList` finds **24**, not the
brief's twenty (the wave-23 verify counted 18 because six carry an `Unsupported` marker and are
reported as unsupported rather than scenario-less). Five are staged and verified through real games;
each of the other nineteen has a verdict below.

## 1. The retarget (CR 115.7, 115.7a) — landed, no ask

E9r answered P22 § 3: `PlayerCandidates` offers the seats behind the objects and `StackTargetsChanged`
carries the new player list. The road is `SmokeScenario.Retarget.cs`.

**The bolt is announced at the opponent, not at the caster.** The brief (and P22 § 3) asked for the
other direction — aim at the caster, retarget to the opponent — and that scenario always passes for
the wrong reason: the runner answers with the *first* option, the options are the objects then the
seats in seat order, the board has no creature, planeswalker or battle on it, so the first option is
seat 0, which is the caster. Answering with the seat the spell already targets changes nothing
(CR 115.7b, and `Retarget` emits no event for an unchanged reading), and `Life(B, 19)` would then be
asserting damage that was never moved. Aimed the other way the same first-legal answer *is* a change:
the bolt moves from the opponent to the caster, and `Life(A, 19)` fails without the retarget.

`SmokeFillers.Cast` is the new reading of which filler spell a target's filter admits, so the same
code answers a counter and a retarget; `SmokeBoard.SpellOnTheStack` now takes the filler's name and
the targets that filler announces.

## 2. **Ask (E9-series):** a keyed retarget target changes nothing (CR 115.7 with CR 608.2h)

`30ec73ad` (Imp's Mischief) is `ChangeTarget { What: Target { Filter: { Spell: true }, Key: "k1" } }`
followed by `LoseLife { N: ManaValueOf { Of: Remembered "k1" } }`. With the key on the target the play
does **nothing at all** — `Life(A)` is 20, so neither the moved damage nor the life for the spell's
mana value happened; the identical definition without a key (`c20a96f7`, Bolt Bend) verifies 1/1 on
the same board. Two halves of one gap, and the second is the reason the first is not just cosmetic:

1. the retarget itself does not fire when its own target carries a key — the unkeyed announcement is
   what `Objects(run, change.What)` reads back;
2. `ManaValueOf { Of: Remembered k }` over a keyed *stack* object reads no number (CR 202.3 — a spell
   on the stack has a mana value).

Owner: `MtgEngine.Rules` (interpreter/targeting, `EffectInterpreter.Retarget.cs` and whatever answers
`Remembered` for an announced target). Until it is answered the generator refuses a keyed retarget —
`ScenarioStageTestsWave24.A_retarget_that_keys_its_target_gets_no_scenario` is the record of it and
flips to a play when this lands. Imp's Mischief is the only corpus card waiting on it.

Three readings did it. `SmokeFillers.Cast`/`Casts` reads a *spell* filter against the fillers' printed
type lines, so a counter no longer needs a filter that says nothing but "a spell" (CR 601.2c);
`NotColors` joins the fields a filler can honour, and a filler that prints no colour is not black
(CR 202.2b); and a `Move { To: Hand }` off a battlefield puts the body in **its owner's** hand rather
than the caster's (CR 400.7).
