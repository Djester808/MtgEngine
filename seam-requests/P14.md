# P14 — the credit-bound rounds as one command each, rehearsed off the network

No engine seam is requested: nothing here touches `Seams.cs`, an event, a state record or
`MtgEngine.Cards`. One wiring change is requested, in `MtgEngine.Cards.Pipeline/Program.cs`,
which P14 does not own — the two `case` arms below. Everything else is built and tested inside
`Translate/`, `Verify/` and the pipeline tests. **Nothing in this wave reached the API**: the
re-translation round is selected, printed and rehearsed against `FakeTranslationClient`, and the
status command never leaves the file system.

## 1. The selection (`Translate/RetranslateSelection.cs`)

`RetranslateSelection.Select(CardDirectory, RetranslateKinds)` reads `cards/` and answers which
faces a re-translation round would submit, with the reason on each. The spec is a comma-separated
word list — `disputed`, `unsupported`, `failed`, `all` — and `disputed,unsupported` is the default;
an unknown word is refused rather than quietly selecting nothing, because an empty batch and a
cheap batch look the same from the outside.

The rule the selection exists to enforce: **a Verified card carrying no `Unsupported` marker is
never submitted, whatever kinds were asked for.** Re-translation is the credit-bound half of the
loop, and resubmitting a verified card spends money to be told what the file already says. An
`Excluded` card is skipped too. Over today's `cards/` that is the 105 disputed plus the 4 marked,
and none of the 83 verified. `RetranslateSelection.Cards(corpus, selection)` maps the selection
onto corpus faces and reports the ids this checkout's corpus does not cover instead of dropping
them (the corpus is not in git).

`TranslateStageRetranslateTests` proves all of it, including a full `TranslateStage.Run` against
the fake client: exactly the three selected ids are submitted, no verified id is, and the request
carries the current prompt version and the whole vocabulary.

**Wiring requested** (one arm, `Program.cs`, after `pilot-submit`):

```csharp
case "retranslate-submit":
    {
        var cardsDir = Positional(args, 1) ?? Path.Combine(root, "cards");
        var outDir = Positional(args, 2) ?? Path.Combine(root, ".agents", "retranslate");
        if (!RetranslateSelection.TryParse(Flag(args, "--only"), out var kinds, out var error))
        {
            Console.Error.WriteLine(error ?? "no re-translation kind was named");
            return 64;
        }

        var selection = RetranslateSelection.Select(CardDirectory.Load(cardsDir), kinds);
        RetranslateSelection.Print(selection, Console.Out);
        if (args.Contains("--dry-run", StringComparer.Ordinal))
            return 0;

        var batch = RetranslateSelection.Cards(Corpus.All(Corpus.LoadRaw(Corpus.DefaultPath(root))), selection);
        return await Pilot.SubmitAsync(PilotEnvironment.ForRepo(root, repair: true), batch.Cards, outDir, cts.Token);
    }
```

`Pilot.Select` takes a count, not a set, so the submit path needs the batch's cards passed
straight in; if `Pilot.SubmitAsync`'s signature does not admit that, the arm belongs to whoever
owns `Pilot.cs` and P14's selection is the input it should use. `--dry-run` is what makes the
round rehearsable for free, and it is the flag the user should reach for first.

## 2. The prompt covers the later records (`Translate/TranslationPrompt.cs`)

`VocabularyReference.OneSpelling` says how the pilot-era records are spelled. The records the
vocabulary gained in V6 and V7 had no such rule, so the model had the record in front of it with
nothing saying which of two readings to write — the shape that cost the pilot most of its 105
disagreements. `TranslationPrompt.LaterSpellings` adds one rule each, with the CR reference, for
`MayPay`, `TappedForMana`, `ManaSpent`, `CreatedTokenThisTurn`, `HasBasicLandType`, `PayOnlyFrom`,
`OfPlayer`, `AttachedPlayer`, `Devotion.ChosenColorKey` and the chosen-colour `ManaProduction`
(with `ManaColors` named as a scenario field a definition must never carry). It is appended to the
system prefix, so the prompt version hash changes with it and no old reading is mixed with a new
one.

`TranslateStageReferenceTests` holds three lines: every record in the name tables is named by the
reference or by the schema; each of the later records has a spelling rule; and the cached prefix
stays under the four-characters-a-token budget an answer needs (`AnthropicTranslationClient`
allows 16,000 output tokens, so the prefix must stay under ~64,000 characters — it is well inside).

`VocabularyReference.cs` is not P14's file. If the coordinator would rather keep all the spelling
rules in one place, `LaterSpellings` moves into `OneSpelling` verbatim and the test follows it.

## 3. `status` (`Verify/StatusCommand.cs`)

`pipeline status [cardsDir]` prints, in one line, the five counts a verification run reports —
verified, failed, with no scenarios, unsupported, not run — plus disputed, untranslated, excluded,
the file count and the engine hash the files were verified against, then one line per unsupported
reason with how many cards wait on it. It reads; it never plays, never writes and never reaches
the network, and `VerifyCommandStatusTests` proves the directory is byte for byte unchanged after
a run. A card whose verification crashed leaves no record in its file, so it appears here as "not
run"; only the run's own log names a crash.

**Wiring requested** (one arm, `Program.cs`):

```csharp
case "status":
    return StatusCommand.Run(Positional(args, 1) ?? Path.Combine(root, "cards"), Console.Out);
```

and both new commands added to the usage line.

## 4. The three rounds, and what each costs

The only measured unit is the pilot's: **200 faces through two translators, unrepaired, ≈ $19**
(`CARD_ENGINE_PLAN.md` § "Decision points"), so **≈ $0.095 a face for two models, ≈ $0.05 a face
for one**. Every figure below is that unit multiplied out — an estimate from the pilot's measure,
not a second measurement — and each round is submit, then collect, then verify, because a batch
takes hours and a process that waits on one holds the corpus and the dll for as long as it waits.

Run `pipeline status cards` first. It costs nothing and it says whether the round is still needed.

| Round | The three commands | Faces | Estimated cost |
|---|---|---|---|
| Re-translation of what disagreed | `pipeline retranslate-submit cards --only disputed,unsupported` → `pipeline pilot-collect .agents/retranslate` → `pipeline verify cards` | 109 (105 disputed + 4 marked) | **≈ $10** at two models, ≈ $5 at one |
| Rulings as scenarios | `pipeline rulings-submit cards` → `pipeline rulings-collect` → `pipeline verify cards` | the verified cards that have rulings (83 today), one model, one short answer each | **≈ $5**, and under $10 even with the ruling text in every prompt |
| The corpus | `pipeline pilot-submit 3864` → `pipeline pilot-collect` → `pipeline verify cards` | 3,864 deck faces | **≈ $370** at two models, **≈ $185** at one |

Two things worth deciding before the money is spent:

- **The re-translation is the one that answers a question.** The 80% agreement bar is re-measured
  on it, and the four marked cards are the ones the vocabulary has since learned to say. It is the
  cheapest of the three and the only one whose result changes what the corpus run should be.
- **The corpus run at one model costs half and gives up the agreement check.** The pilot's
  agreement number is what the canonical passes and the "one spelling" rules were tuned against;
  running the corpus through one translator makes `verify` the only check, which is a real check
  (a card is verified by being played) but a weaker one for a card whose scenario asserts little.

`pipeline verify cards` is free in every round: it plays, it does not translate.
