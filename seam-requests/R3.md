## 1. The brief's first item was already in, and is now pinned

The brief said `TapForManaStep` reads the printed face. It does not, and has not since wave 21:
`ScenarioRun.ManaAbilityIndex` reads `Host.Engine.Characteristics.Of(...).Abilities`, so the
intrinsic ability E0j put in the layer system (CR 305.6, `Layers.Intrinsic.cs`) is the first — and
only — mana ability a `ScenarioFiller` basic land has, and index 0 is it. **A filler Forest taps for
{G} today.** Nothing in the runner was changed for it beyond the doc comment, which now says where
the ability comes from so the next box does not re-derive this.

It was un-tested, which is why the wave-25 seam files still record it as blocked. Six of the ten
tests here are that pin, and they are not vacuous — **proved by mutation**: swapping the layered read
for `Definition.Faces[FaceIndex].AbilityList` in `ManaAbilityIndex` fails exactly those six
(`Failed: 6, Passed: 42`) with "no mana ability to tap for mana", and nothing else in the anchor.
The five basics are asserted one per colour, so the colour comes from the subtype table and not from
"every land taps for something"; the two typeless land fillers (`Land`, `BasicLand`) are asserted to
still have no mana ability at all, which is CR 305.6's gate and not the land card type.

**So `00d8efa6` (Utopia Sprawl) is unblocked on this half** — R1 § 3, R2 § 3, P20 § 4, P21 § 3,
P23 § 4 can stop carrying it. The other half of that card is unchanged and is the interpreter's:
`Enchant` reads only a `Simple` filter, so `subtypes: [Forest]` is refused before any tap is reached
(P23 § 4). Its `ManaPoolIs` still names the total of the land's own mana plus whatever the Aura adds.

## 2. What `SmokeFillers` must offer — the four coloured bodies (P-series)

P24 § 2's ask is done. `ScenarioFiller` now has `WhiteCreature`, `BlueCreature`, `BlackCreature` and
`RedCreature` beside `GreenCreature`: a 1/1 for one mana of that colour, with the colour indicator
printed as well (CR 202.2, 202.2b), the same shape `GreenCreature` set. All four are in
`ScenarioFiller.Names`, `For`, `ColorOf`, `TypesOf` and `ManaValueOf`, so:

- **`SmokeFillers.Cards()` needs no change** — as P24 § 3 found, it returns the plain list and then
  everything in `Names` not already in it, so the four are offered the moment they exist.
- **The colour a filter names is read off `ScenarioFiller.ColorOf(name)`**, which returns
  `Color.White`/`Blue`/`Black`/`Red`/`Green` for these five and `Color.Colorless` for every other
  filler. Do not parse the cost: the indicator and the cost agree by construction and a test asserts
  it, so one reading is enough.
- **A `Colors:` filter with one colour now has a body to stand.** `9d73a51a` (Brave the Elements) —
  `Apply { GrantKeyword Protection, To: Each { Types: Creature, ControlledBy: You, Colors: White } }`
  — is the shape: stand `WhiteCreature`, and the continuous effect has a non-empty set, so the event
  the scenario asserts is logged (CR 611.2c is what made the wave-24 attempt fail). The honest arm
  P24 built — stand the body the filter describes, refuse when there is none — now has an answer for
  four more filters instead of a refusal.
- **Multiple colours in one filter is still a refusal, and should stay one.** There is no
  multicoloured filler and no colourless *creature* with an indicator: a filter naming two colours
  (a gold body) or "colorless creature" describes a permanent the board cannot stand, and standing a
  mono-coloured body for it would assert the wrong card. `ScenarioFiller.Creature` is colourless by
  CR 202.2 (no cost symbols of colour, no indicator) and `ColorOf` says so, so a "colorless creature"
  filter can be answered with it if the P-series wants that arm — it is a generator reading, not a
  filler gap.
- **Ordering**: the four sit between `GreenCreature` and `Bolt` in `Names`, i.e. after the basics and
  before the bolt. Nothing reads the order except `Cards()`'s tail, and no filter admits both a
  coloured body and a land, so this changes no existing result. Checked: the whole
  `ScenarioRunnerTests` anchor is green with the list as it now stands.

## 3. What is still not offered, recorded so the next box does not re-derive it

- **No coloured body with a keyword, and no coloured non-creature.** "Target white permanent" or
  "each red creature you control gains flying" is standable; "target blue instant" is not (the
  fillers' instants are `{1}` and `{R}` — `Spell` is colourless, `Bolt` is red by its cost but
  carries no indicator, so `ColorOf(Bolt)` says `Colorless` and disagrees with CR 202.2). If a card
  ever needs a coloured spell, the fix is an indicator on `Bolt` or a new filler, and it is one line
  here — ask for it rather than parsing the cost in the generator.
- **No two-colour body**, as § 2 says.
- CR 605.1a is still read in three private copies (`CastingSystem.ManaAbilities`,
  `Query.Predicates`, this runner) and none of them checks the rule's fourth criterion — an ability
  whose cost or effect moves a card to or from a library is not a mana ability. R2 § 4's ask stands
  unchanged; every basic land now carrying an intrinsic ability makes the three agreeing more
  load-bearing, not less. Still a cross-folder change no folder here owns.
