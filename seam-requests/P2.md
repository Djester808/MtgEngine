## `tests/MtgEngine.Pipeline.Tests/SmokeTests.cs` line 1 fails the build (pre-existing)

`tests/MtgEngine.Pipeline.Tests/MtgEngine.Pipeline.Tests.csproj` does not build on a clean
worktree, and it is not my change that breaks it:

```
tests/MtgEngine.Pipeline.Tests/SmokeTests.cs(1,1): error IDE0005: Using directive is unnecessary.
```

`SmokeTests.cs` opens with `using MtgEngine.Cards.Pipeline;` and then declares
`namespace MtgEngine.Cards.Pipeline.Tests`, so the using is redundant — the enclosing namespace
already resolves `VocabularyReference` and `Translator`. `Directory.Build.props` sets
`EnforceCodeStyleInBuild` with `TreatWarningsAsErrors`, so IDE0005 is an error and the whole test
project (mine included) refuses to build.

**Fix:** delete line 1 of `SmokeTests.cs`. One line, no behaviour change. I do not own that file,
so I have not touched it.

## `CorpusCard.IsFreeSlice` over-counts, and the pilot uses it to skip cards

`Templates.IsKeywordOnly` (in `MtgEngine.Cards.Pipeline/Corpus.cs`, which I do not own) accepts a
line when its **first word** is one of the card's Scryfall keywords. Scryfall's `keywords` array
includes **ability words**, so "Landfall — Whenever a land you control enters, this creature gets
+2/+2 until end of turn." is admitted as keyword-only. Measured over the corpus:

| measure | cards |
|---|---|
| `IsFreeSlice` says free | 5,652 |
| …of those, with a type line that parses at all | 3,066 |
| …the rest: art series (`Card`) 2,575, `Token` 10, `Stickers` 1 | 2,586 |
| ability-word and other non-keyword lines inside that 3,066 | ~953 |
| what the template stage actually builds | 2,428 cards / 2,462 faces |

Two consequences for other stages:

1. **The 2,990 in my brief is that 3,066 number, not a stage count.** The honest free slice is
   2,462 faces; `TemplateStageTests.Corpus` asserts a floor of 2,400 and prints the whole
   breakdown so nobody has to take it on trust.
2. **`Pilot.RunAsync` skips `card.IsFreeSlice`**, so those ~953 ability-word cards are skipped by
   the translator *and* refused by the template stage — they fall through the gap. Whoever owns
   `Corpus.cs` should either tighten `IsKeywordOnly` (require the whole part to be a keyword, and
   split on `,\s*` rather than `,\s*(?=[A-Z])`, which today also misses "Flying, vigilance") or
   have the pilot skip on `TemplateStage.Accepts(card)` instead.

## `Corpus.Card` resolves tokens in O(cards × parts)

`Corpus.Card` finds each `all_parts` token by scanning `raw.Values` for a matching `id`. Over the
whole corpus that is a quadratic scan: my corpus test took **8 min 31 s** through `Corpus.Card`
and **8 seconds** reading the same fields directly. A dictionary from Scryfall `id` to card, built
once in `LoadRaw`, would fix it. The test reads the bulk file itself for now and says why.

**What I did instead:** verified my anchor by building the test project with
`-p:NoWarn=IDE0005` and running `dotnet test --no-build --filter FullyQualifiedName~TemplateStageTests`.
That flag is only on my command line; nothing in the repo suppresses the rule, so the gate will
still fail on `SmokeTests.cs` until the line goes. `tools/build.sh` cannot run this anchor until
then.
