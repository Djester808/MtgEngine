# V1 — the three evaluator arms the new vocabulary primitives owe

E12 stopped on three missing records (`seam-requests/E12.md` §1–3). All three now exist in
`MtgEngine.Cards`, are in the name table, are in the committed schema, and lint clean:

| Record | File | Rule |
|---|---|---|
| `IsThisObject` — a `Predicate` | `MtgEngine.Cards/Selectors.cs` | CR 109.5, 603.2 |
| `DiscardSelfCost` — a `Cost` | `MtgEngine.Cards/Costs.cs` | CR 702.29a |
| `bool AllCreatureTypes` on `AddTypes` | `MtgEngine.Cards/Continuous.cs` | CR 702.72a, 205.3d |

`IrVersion.Current` is **not** bumped and must not be: all three are additions with defaults, so
every card file written before them deserialises unchanged (`VocabularyAdditionsTests
.A_definition_written_before_the_flag_existed_still_reads` holds that line). `Files.cs` is not
V1's to edit in any case.

A card can now be *translated* into all three. None of them *plays* yet — each needs one arm in
a folder V1 does not own. Until those land, a definition carrying one is accepted by the
serializer and the linter and then fails in the engine, so these are the three follow-ups.

## 1. `Rules/Query` must answer `IsThisObject`

`MtgEngine.Rules/Query/Query.Predicates.cs` falls through to
`_ => throw Unanswerable(predicate.GetType().Name, "no arm in the query layer")`, so today every
"whenever this creature …" trigger throws at match time rather than failing to compile. The arm:

```csharp
// CR 109.5: "this" is the object the ability is on.
IsThisObject => ctx.Source is { } source && source == candidate,
```

`EffectContext.Source` is `ObjectId?` — an ability evaluated with no source matches nothing here
rather than matching everything, which is the safe reading of a filter that names an object that
is not there. It is the object the ability is printed on, which is exactly what CR 109.5
defines "this" to mean, and CR 603.2 matches a trigger's event against its own source like any
other object. Two neighbouring meanings must stay apart: `ObjectFilter.Other` is "another" and
*excludes* the source; a filter with neither marker matches any object it describes, including
the source. The selector `Self` is the same idea on the effect side and already resolves to the
source, so the two should agree by construction — resolve `Self` and compare, or read
`ctx.Source` directly, but not two different notions of "the source".

Unblocks undying (CR 702.92a), persist (CR 702.79a), afflict (CR 702.131a), mentor
(CR 702.135a), and the large share of the deck slice whose text begins "Whenever this
creature…".

## 2. `Rules/Casting/CostPayment` must pay `DiscardSelfCost`

CR 702.29a: cycling is "[Cost], Discard this card: Draw a card." The cost discards **the card
the ability is on**, and no other card may pay it. `DiscardCost` — "discard a card", the player
chooses which — is a different cost and is not a legal substitute; E12's expander emitted the
wrong one only because this record did not exist yet (`KeywordSemantics.Costs.cs` records the
note).

Payment is a zone change of `ctx.Source` from hand to graveyard (CR 701.9a), and it is a cost,
so it happens as the ability is activated, not on resolution — which means the card is already
in the graveyard while the ability is on the stack. Legality: the cost is unpayable if the
source is not in the payer's hand.

Also wanted by jump-start and the madness-adjacent readings when those arms are written.

## 3. `Rules/Layers` must apply `AddTypes.AllCreatureTypes` in layer 4

CR 613.1d, layer 4: the object is **every** creature type (CR 205.3d), which is what changeling
grants (CR 702.72a). Changeling is characteristic-defining, so it applies in layer 4 in
timestamp order with everything else that changes types; `StaticAbility.CharacteristicDefining`
is already on the record.

The constraint that makes this a seam request rather than an implementation detail: **no list of
creature types may appear in `MtgEngine.Rules`.** Plan rule 1 — a card is data or it does not
exist — and the list changes every set, so a literal list would be stale card data in engine
source. Two ways out, either acceptable, one of them chosen once:

- `Characteristics` carries `bool AllCreatureTypes`, and every subtype test
  (`HasSubtype`, `SharesTypeWith(CreatureTypeOnly: true)`, `IsChosenType`, tribal filters)
  answers true for any creature type when it is set. Nothing enumerates.
- The set of creature types is derived at startup from the parsed rulebook (CR 205.3m lists
  them) and injected, never written in C#.

Note that this interacts with `SharesTypeWith`: a changeling shares a creature type with every
creature, which the first option gets right only if `SharesTypeWith` consults the flag rather
than intersecting two subtype lists.

## Not asked for

E12 §4 (affinity's `CostModifier` matching "this spell") is closed by `IsThisObject` as filed:
`ObjectFilter(Spell: true, Also: new IsThisObject())` now says it. No further record is needed;
whether affinity expands at all is E3's call, per E12's own note.

E12 §5 (riot) needs no record, only E8's replacement subsystem.

`Linter.cs` needed no change. L003 keys off the records that carry a `Key` string, L004 off
`Fixed`, L005 off `KeywordAbility` parameters and L006 off `CounterKindOf` — none of them
enumerates predicates, costs or continuous effects, and `Linter.Walk` is reflective, so the
three additions are walked, neither flagged nor skipped.
`VocabularyAdditionsTests.All_three_additions_lint_clean` asserts it.
