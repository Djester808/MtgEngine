# V10 — wave 17 vocabulary: the two shapes the third reading could not say, and the output rules

Both records below landed in `MtgEngine.Cards` this wave, lint where their rider can say nothing,
round-trip in `VocabularyAdditionsTests.Wave17.cs`, and have a one-spelling line in
`TranslationPrompt.LaterSpellings`. `IrVersion` is unchanged at 1: one optional list on `Search` and
two optional members on `ChooseMode`, so a card file written last wave still reads. The schema
snapshots under `cards/schema/` are regenerated (`UPDATE_SCHEMA=1`, the deliberate road, as V8 and
V9 did); nothing else under `cards/` was touched. The prompt renders (`pipeline prompt`, 604 lines)
and now carries an "Output rules" block between the instructions and the later spellings.

Neither record is played by anything yet. Each row names the arm that has to read it and the card
it unblocks.

## Decisions taken here

- **Item 1 is a list on `Search`, not an `If` around one and not a new effect.** The condition is the
  card found, which nothing outside the search can name: an `If` would read a filter against
  something else, and a second `Search` would see the library twice and shuffle twice (the L019
  reasoning, wave 13). `SearchDestination` is a plain record beside `CounterSpec`, and its filter is
  read against the one card found, so it carries no zone.
- **L023 is an Error, where L019's equal-zone case is a Warning.** An `OthersTo` equal to `To` is a
  redundant word; an `Instead` entry equal to the plain destination means the "instead" half of the
  sentence was lost, which is a different card. The same code refuses an empty list and an entry
  that taps a card outside the battlefield (the L019 rule again).
- **Item 2 is `MaxIf` with `MaxIfMet` on `ChooseMode`**, not a `Condition`-valued `Max`, so a stored
  file's integer `max` still reads and the IR version stays. L024 refuses either half alone and a
  `MaxIfMet` not above `Max`, which would raise nothing.
- **The rule cited.** The brief named CR 700.2d for the mode count; that rule is the same-mode-twice
  rule (`SameModeTwice` already cites it by way of 700.2). The count is CR 700.2 and the moment it
  is read is the announcement, CR 601.2b, so the doc, the lint and the prompt cite those two.
- **The output rules are computed, not typed.** `TranslationPrompt.OutputRules` names the bases that
  carry a `kind` by reading `CardFileSerializer.PolymorphicBases` and keeping the ones the
  definition schema's `$defs` defines — which is exactly the set of "… kinds" sections the reference
  prints, and `TranslationPromptTests` proves the two lists equal. The rule then names the plain
  records (`CardDefinition`, `Face`, `TypeLine`, `PrintedStat`, `ObjectFilter`, `ManaProduction`,
  `Comparison` and the rest of the reference's root section, plus `SearchDestination`) as objects
  with no `kind`, and says the parser refuses any other member by name. The rule sits in
  `SystemWithVocabulary`, so the prompt version changes with it and stored readings do not mix.
- **`Linter` gained a third partial**, `Linter.Conditionals.cs`, for L023 and L024; `Linter.cs` is
  at 492 lines and `CheckAbility` calls `CheckConditionals` beside `CheckPermissions`.
- **`RuleRef`s added**: `SearchDestination` 701.23a. `Search` keeps 701.23 and `ChooseMode` 700.2.

## Asks (outside `MtgEngine.Cards/**`)

1. **E-series (interpreter)**: the `Search.Instead` read in row 1 — per card found, first entry
   wins, filter read against the card where it lies, else the plain destination. Then re-verify
   `27e9db49` once its file is redone.
2. **E-series (casting)**: the `MaxIf` read at announcement in row 2 — the ceiling of the mode
   question comes from the condition, evaluated once, for a cast spell, an activation and a
   triggered ability alike. Then re-verify `fd949f82` once its file is redone.
3. **P-series (reference)**: `VocabularyReference.cs`'s root section is a hand-written list and is
   not owned here; add `typeof(SearchDestination)` beside `CounterSpec` so the translator sees its
   three parameters as a line of their own. Until then the fields are named in the `Search` doc,
   the one-spelling line and the output rule, which is enough to write the object but not the
   reference's usual shape. `TranslateStageTests.Reference.cs`'s `Later` list could name
   `Instead` and `MaxIf` so the one-spelling test proves their lines exist; the lines are there.
4. **Coordinator / pipeline**: refresh both `system.md` files (the prompt text changed in two
   places) and redo the two cards on three models. A reading that spells item 1 as an `If` around
   a `Search`, or item 2 as an `If` around a `ChooseMode`, is a real disagreement with the new
   spelling and not a canonical rewrite — the prompt now says so, so a fresh reading should not
   produce it.

## Not done in this box

- No lint that an `Instead` entry's `Matching` is a subset of `For`: the linter does not compute
  filter subsumption, and an entry that admits nothing the search can find is harmless at play.
- No lint that `MaxIfMet` is at most the number of modes; `Max` has never had one either.
