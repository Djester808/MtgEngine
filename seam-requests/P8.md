# P8 — seam requests

Measured with `dotnet run --project MtgEngine.Cards.Pipeline -- verify cards` in this worktree
after the changes below: **55 verified, 6 failed, 24 with no scenarios, 2 crashed** over the 87
Translated-or-Verified card files (`engine:d3f92087a7896a2b`). Every item here is one of those
six or two, and none of them is in a file I own.

## 1. `CastSpell` still has nowhere to pay a printed additional cost (CR 601.2f)

`Commands/Command.cs`'s `CastSpell` carries `CostChoices` (strings a cost's own choice reads) and
`OptionalCosts` (keywords), but nothing that says "and I sacrifice this creature to cast it".
`CastingSystem` therefore refuses every spell whose face has `AdditionalCosts`:

```
FAILED Village Rites: The engine refused CastSpell: An additional cost printed on a spell cannot be paid yet. (601.2f)
```

So the smoke scenario does **not** supply a choice for one, as my brief allowed. When E3c adds the
field, one arm in `SmokeScenario.Of` supplies the cheapest legal payment — for a sacrifice cost the
board already knows how to place a body (`SmokeBoard.Body`) — and the guard to add is a refusal to
generate a scenario for an additional cost the board cannot pay, rather than one that fails.

## 2. A generated scenario cannot answer the question a search asks (CR 701.19, 616.1)

Three of the six failures are tutors:

```
FAILED Demonic Tutor / Diabolic Tutor / Grim Tutor: InZone was Stack
```

The spell resolves as far as the search, the search asks which card to take, `ResolveAllStep` stops
because `_state.Pending is not null`, and the spell is still on the stack when the expectations are
checked. The scenario is right and the run is honest; what is missing is a way for a *generated*
scenario to answer a question whose option ids it cannot know when it is written. Two shapes, either
of which I would use:

- a `ScenarioStep` that means "answer the pending question with its first legal option", so a smoke
  scenario can carry one without naming an option; or
- `ScenarioRunner` answering a question raised by a step the scenario itself did not ask for, when
  the scenario says so — a flag on `ScenarioSetup`, not a default, because a scenario about a choice
  must still be able to make it.

`Scenarios.cs` is `MtgEngine.Cards` (V-series) and the resumption is E13/E9d's; the runner change is
mine once the step exists. The same gap keeps a land whose ETB trigger asks a question off the
verified list — it is why the land scenario no longer asserts `StackEmpty` (CR 305.9: the play does
not use the stack, so what is left on it is about the card's triggers).

## 3. An Aura's smoke scenario has nothing to enchant (CR 704.5m)

```
FAILED Song of the Dryads, Kenrith's Transformation: InZone was Graveyard
```

Both are Auras: the permanent arm expects the battlefield, the spell arrives unattached, and the SBA
puts it straight into the graveyard. The board can place a body already; what it cannot read is what
the face enchants, because `Face` carries no enchant target — the "enchant X" restriction is not in
the vocabulary as a field a generator can see (it is prose or a static). Either V-series adds
`Face.Enchant` (an `ObjectFilter`), or the smoke generator has to refuse every Aura, which is what I
would do in the meantime and did not, because refusing them silently hides two cards that are one
field away from verifying.

## 4. The two crashes are engine arms already owed, and no longer stop the run

`VerifyCommand` now catches per card, records the exception's type and message as the first failing
expectation's actual, counts it as `crashed` and carries on; the run exits 0 whatever it finds,
because a failing card is the measurement and not an error.

```
CRASHED The One Ring: NotImplementedException: CastThisTurn cannot be answered by the query layer yet …
CRASHED Talon Gates of Madara: NotImplementedException: no interpreter arm for PhaseOut
```

The first is E0b's `CastThisTurn` (wave-5 row in DECISIONS), the second an interpreter arm nobody has
claimed — `PhaseOut` is not in E9d's list. One card, so it is worth a line in the backlog rather than
a builder.

## 5. Nothing else

`ScenarioRun.Place` now resolves the alias before the name and places Hand before Library, and a
placement no longer names itself after its definition, so P7's § 2 is closed: a scenario can stock a
library with copies of the card under test and still cast the one in hand
(`ScenarioRunnerTests.A_library_stocked_with_copies_of_the_card_still_casts_the_one_in_hand`). The
library filler is `ScenarioFiller`, three made-up definitions the runner supplies itself, so no
generated scenario names a real card it is not testing. The pilot prints
`AgreeReport.Of(results).Text()` in its report (P6 § 1).
