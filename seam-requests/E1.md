# E1 — seam requests

Four things the zone system needed and could not have. None of them blocked the rest of the
work; each is written as the smallest change that closes it.

## 1. Nothing can record that a card was drawn

`PlayerState.ObjectsDrawnThisTurn` exists and `TurnBegan` resets it, but no event increments
it, so `IZoneSystem.Draw` cannot maintain it: a draw is an `ObjectMoved` from library to hand,
which is indistinguishable from a "put the top card of your library into your hand" effect —
and CR 121.2 says those are different events, which matters for "if you would draw a card"
replacements (CR 121.6) and for triggers on drawing.

**What I need:** an event in `Events/GameEvent.cs`

```csharp
[RuleRef("121.1")]
public sealed record ObjectDrawn(PlayerId Player, ObjectId Object) : GameEvent
{
    public override GameState Apply(GameState state)
    {
        var p = state.Player(Player);
        return state with { Players = state.Players.SetItem(Player.Value, p with { ObjectsDrawnThisTurn = p.ObjectsDrawnThisTurn + 1 }) };
    }
}
```

emitted by `Draw` after the `ObjectMoved`, and added to `tests/MtgEngine.Rules.Tests/events.txt`.
Without it `ObjectsDrawnThisTurn` is dead state and a draw is not nameable in the log, so
E6's triggers and E8's replacements have nothing to match on.

## 2. `CreateToken` cannot say what the token attacks

`CreateToken(state, token, controller, tapped, attacking)` takes a bool, but CR 508.1 says an
attacker attacks a player, a planeswalker or a battle, so "attacking" is not a boolean fact.
Right now the token joins whatever the other attackers are attacking, and with no attackers it
picks the one other player who has not lost — correct for two players, a guess for more.

**What I need:** `CombatTarget? attacking = null` in place of the bool on `IZoneSystem.CreateToken`,
or an overload taking one. Same for "blocking", which some effects also grant.

## 3. `Move` moves one object at a time

CR 400.7 / 704.5m turn on simultaneity: several objects put into a graveyard at once are one
event, and "leaves the battlefield" triggers see the board as it was before any of them left.
A loop over `Move` gets a different board for the second object than for the first.

**What I need:** `Outcome MoveAll(GameState state, IReadOnlyList<MoveRequest> moves)` on
`IZoneSystem`, with `MoveRequest(ObjectId What, ZoneKey To, Placement Where, bool Tapped, PlayerId? Controller)`.
E5 (state-based actions) and E4 (combat deaths) are the callers that need it first.

`Placement.AnyOrder` and `Placement.RandomOrder` are also unreachable through a single-object
`Move`: ordering several cards is one choice (CR 401.4), so those two want the batch form too.
Today they behave as `Placement.Default`.

## 4. `GameSetup` has no starting player and no mulligan hook

CR 103.1: the starting player is chosen before decks are shuffled, and CR 103.4/103.5 put the
mulligan between the opening hand and turn 1. `GameSetup` has seats and a seed, so `Create`
deals seat 0 first and `ITurnSystem.Begin` has to assume seat 0 goes first.

**What I need:** `int StartingPlayer = 0` on `GameSetup` (or a `PlayerId StartingPlayer`), so
the choice is in the setup rather than implied by seat order. Mulligans stay E13's, but they
need the opening hands to exist first, which they now do.

## Conventions this landing fixed, for the record

Not requests — decisions the zone system had to make, written down so no other builder makes
the opposite one:

- **Shared zones carry no player in their `ZoneKey`.** CR 400.1: library, hand and graveyard
  are a player's; battlefield, stack, exile and command are shared. `ZoneSystem.KeyFor` and
  `ZoneSystem.IsOwnerZone` are public so every subsystem builds the same key, and `Move`
  normalises whatever key it is handed (which is also how CR 400.3 is enforced).
- **Libraries and graveyards are top-first; the stack is bottom-first.** So index 0 is the top
  of a library or a graveyard and the *bottom* of the stack, and `Placement.Top` means index 0
  in the first two and the end in the stack. `Placement.Default` is the top for a library or a
  graveyard (CR 404.1) and the end everywhere else.
- **`Move` on an object that is not in `state.Objects` returns `Outcome.Unchanged`**, not a
  refusal: an effect that names an object which has already left simply does nothing.
- **A `RngAdvanced` is emitted only when the generator actually advanced.** `Rng.Shuffle` of a
  library with fewer than two cards draws nothing; the `ZoneReordered` is still emitted, so
  "the library was shuffled" triggers (CR 701.24e) still have their event.
