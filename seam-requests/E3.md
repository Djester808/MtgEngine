# E3 seam requests — mana, costs, casting, the stack

Three seams pinch. None of them blocked the slice; each is worked around inside
`Rules/Casting` and `Rules/Stack` in a way the note names, so the coordinator can decide
whether to change the seam or keep the workaround.

## 1. E2 must call `CastingSystem.EmptyPools` as each step and phase ends (CR 106.4)

`ICastingSystem` has no member for it, so the method is on the concrete
`MtgEngine.Rules.Casting.CastingSystem`:

```csharp
public Outcome EmptyPools(GameState state);   // ManaPoolEmptied per player with mana
```

It returns one `ManaPoolEmptied` per player whose pool is not empty, and nothing when every
pool is empty, so it is safe to call at the end of every step. The turn system is the only
caller. Either add it to `ICastingSystem` (my preference — then `Subsystems.Casting` can call
it without a cast) or have `Game` own the call in the step-end path; today nothing calls it
and mana would carry across steps, which CR 106.4 forbids.

## 2. `IZoneSystem.Move` cannot carry a `StackEntry`, so casting builds the move itself

CR 601.2a puts the card on the stack **as a new object holding the targets, modes and X**.
`Move(state, what, to, where, tapped, controller)` has nowhere for that, and `ObjectChanged`
has no `Stack` field either, so a move-then-patch is not possible. `Rules/Stack/StackZone.cs`
therefore constructs the `ObjectMoved` for the hand-to-stack move itself (`MoveSpellToStack`)
and the `ObjectCreated` for an activated ability (`CreateAbilityOnStack`). Every other zone
change in casting — a land to the battlefield, a permanent spell resolving, a sacrifice, a
spell to the graveyard — goes through `IZoneSystem.Move`.

If you would rather all zone changes went through E1, `Move` needs an optional
`StackEntry? stack = null` parameter (or a dedicated `PutOnStack`), and E1 has to leave the
entry on the created object.

## 3. `AbilityActivated.StackObject` is not nullable, and a mana ability has no stack object

CR 605.3a: activating a mana ability does not use the stack. The event's first field is a
non-nullable `ObjectId StackObject`, so for a mana ability I pass the **source's** id, which
reads as though the ability were on the stack. Suggested change:

```csharp
public sealed record AbilityActivated(ObjectId? StackObject, ObjectId Source, int AbilityIndex, PlayerId Player)
```

with `null` meaning "did not use the stack". E6 will need that distinction to tell a mana
ability's activation (CR 605.1b) from an ordinary one.

## Smaller notes, no seam change needed

- Casting is from hand only in this slice; anything else refuses with CR 601.2a. Alternative
  and optional costs, additional costs on a face, and casting another face refuse naming
  601.2b, 601.2f and 712 rather than being ignored.
- Phyrexian mana does not parse yet (CR 107.4f needs a life payment during cost payment).
  `ManaSymbols.TryParse` returns false and says so.
- `{S}` is paid with one mana of any type; whether the source was snow is not tracked, since
  nothing in the state records a mana's source (CR 106.3).
- Costs paid in this slice: `ManaCost`, `TapSelf`, `SacrificeSelf`, `PayLife`, and `Costs`
  flattened. Every other `Cost` refuses naming itself and CR 601.2h, so nothing is half paid.
