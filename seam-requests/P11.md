# P11 — a scenario for every one of the 16

Measured with `dotnet run --project MtgEngine.Cards.Pipeline -- verify cards` in this worktree,
over a clean `cards/`, before and after:

| | verified | failed | no scenarios | crashed |
|---|---|---|---|---|
| wave-7 tip | 70 | 0 | 16 | 1 |
| this branch | **82** | **1** | **3** | 1 |

`cards/` was reverted before the commit, so the tree carries no card file. The crash is the same
`Unsupported` marker it has been since wave 5.

## 1. One seam I want and did not take: a shuffle is not a `ZoneReordered`

`ScenarioFiller` gained an artifact, an enchantment, a sorcery and a **basic** land (kept apart
from the plain filler land, which stays nonbasic so a "nonbasic" filter still has an answer), and
the smoke board stocks the library with whichever of them a `Search` names — on top, under an
alias, because the runner answers a question with its first legal option, so the card the scenario
stocked is the card the search finds and the expectation can name it.

The shuffle that follows (CR 701.20) is asserted as `EventLogged(nameof(ZoneReordered))`. That is
weaker than it should be: `ZoneReordered` carries `Shuffle`, and the reorder the backlog emits when
a player puts cards back in an order (`EffectInterpreter.Backlog`) is the same event kind. In a
tutor's scenario there is no other reorder, so the expectation is real today, but it would pass a
search that reordered without shuffling.

**Request:** an expectation record in `MtgEngine.Cards/Scenarios.cs` — `Shuffled(string Player)`,
or an `EventLogged` that can name a field — so the assertion is CR 701.20 and not "something was
reordered". Not mine to add; the check in `ScenarioExpectations` is two lines once the record
exists.

## 2. What the 16 became

Twelve of them verify. The four families and what each needed:

- **Destroy target artifact or enchantment** (Disenchant, Nature's Claim, Return to Nature,
  Krosan Grip) — `SmokeFillers.Bodies` reads a target's filter against the filler type lines
  instead of admitting creatures only, and `SmokeBoard.AimedAmong` places every kind the filter
  admits and aims at the first. So "artifact or enchantment" puts one of each on the opponent's
  board, kills the artifact, and the enchantment standing beside it is the control.
- **Go for the Throat, Generous Gift** — the same widening: `NotTypes` and `Permanent: true` are
  now fields a filler can answer rather than fields that refuse a scenario.
- **Tutors** (Idyllic, Worldly, Entomb, Kodama's Reach) — the stocked library, plus the search
  arm now reading `To` for hand, graveyard, battlefield and library-on-top rather than two hard
  cases.
- **Board wipes with modes** (Farewell, Austere Command) — `ChooseMode` takes as few modes as the
  card allows rather than only a `Min: 1, Max: 1`, so "choose one or more" is a choice of one and
  "choose two" is the first two; `Exile { What: Each }` sweeps the same way `Destroy` does; and
  the swept body is whichever filler the filter names, so "exile all artifacts" is a scenario.

## 3. Still without a scenario, and why

- **Chord of Calling** and **Finale of Devastation** — the search filter carries a `ManaValue`
  comparison ("with mana value X or less"). The board would have to place a card of a particular
  mana value, and the fillers have one printed cost each. A filler per mana value, or a
  `Comparison` the board can satisfy by choosing which filler to stock, is the next round's.
- **Harrow** — "Sacrifice a land" is an effect-side sacrifice with a `Choice`, which is now
  handled, but the search is for *up to two* basic lands with a `Placement` that splits them
  between two zones; the generator asserts one found card in one zone and cannot say what the
  second did.

## 4. One failure, and it is the engine's, not the generator's

**Entish Restoration** — `InZone was Stack`: the spell never left the stack, so a question stood
unanswered and `ResolveAllStep` returned with the game waiting (the guard in `ScenarioRun.Answer`
returns when `FirstLegal` has nothing legal to say). This is the "an unanswered question stalls
the game" shape. It is left failing on purpose: it names a real gap in the answering path, where
before it was hidden behind "no scenario".

## 5. `ActivateStep` is exercised now

`SmokeActivation` generates one scenario per activated ability: the permanent starts on the
battlefield (CR 602.2 activates from where the object already is), the cost is paid from the deep
pool, `TapSelf` is asserted as `TappedIs`, `PayLife` as a life total, and a `SacrificeCost` places
its own body and names it in `ActivateStep.CostObjects`. An ability whose cost the board cannot
arrange — a counter to remove, a card to exile from a zone, a choice between costs — gets no
scenario.

One arm had to be closed after the first verify run: an ability that adds **one mana of any
colour** is refused ("The colour of mana to add was not chosen", CR 608.2d) because the choice
travels with the command and a generated scenario has no way to make it. Five cards failed that
way; they now get no activation scenario. If `AnswerChoice` ever answers a mana colour, or
`ActivateStep` grows a colour, those five come back.
