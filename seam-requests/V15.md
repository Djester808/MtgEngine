## Decisions taken here

- **Prevented damage is its own amount, not a flag on `TriggeringDamage`.** V14 set the precedent
  with the two life amounts, and the reason is the same and sharper here: dealt and prevented are two
  numbers on one event, and full prevention makes the dealt one zero. A flag would let the wrong
  number be read by flipping a bool — exactly what L043 exists to catch.
- **"Any other target" is a flag on `AnyTarget`, not a filter.** "Any target" reaches a player, a
  planeswalker and a battle; an `ObjectFilter` reaches none of the first and only some of the rest,
  so writing the exclusion as a filter silently drops three quarters of the phrase.
- **`DamageCantBePrevented` is a `ContinuousEffect` and not a field on `PreventDamage`.** One record
  makes prevention happen and the other makes it not happen; a nullable "inverted" flag on the first
  would make every existing `PreventDamage` a candidate reading for the opposite sentence.
- **`PlayWithTopCardRevealed` is not `MayLookAtTopCard` with a bool.** The two are the two halves of
  CR 401.5 and differ only in who sees, which is precisely the half a merged reading loses. A
  `Public` flag on the existing record would have been the same mistake `IsModified` avoided.
- **`Placement.BottomRandomOrder` is one member, appended last.** Appending keeps every stored
  file's placement name valid (the serializer writes names, but a positional reading of the enum
  would have shifted) and keeps `IrVersion` at 1.
- **`MoveCounters.AnyNumber` is a third flag, not `N: null` meaning "any".** `N: null` already means
  one counter on every stored file; giving it a second meaning would change the reading of cards
  already committed.
- **RuleRefs added, every number read in `comprehensive-rules.txt` first.** `DamagePrevented` and
  `TriggeringPreventedDamage` **615.13** (the brief said "CR 615 with 603.10"; 615.13 is the rule for
  triggered abilities that trigger on prevention); `DamageCantBePrevented` **615.12** (the brief's
  guess, confirmed); `PlayWithTopCardRevealed` **401.5** — the brief guessed 701.15, which is
  **Goad**; the "play" in the phrase is CR 701.18c and the new-object rule is 401.6;
  `ManaSpentOnTriggering` **400.7d** — the brief guessed 601.2g, which is *activating mana
  abilities*; 400.7d is the rule that lets a later ability read what was paid, and 601.2h is where
  the payment happened; `MoveCounters` **122.5** (confirmed); `Counter` **701.6** already, and the
  placement clause cites **701.6a** — the brief said 701.5a, which is **Cast**; `SpellCast`
  **603.2** (confirmed); `Placement` **401.4** in the doc comment (there is no rule that names
  "bottom in a random order"; 401.4 is the default ordering the printed line overrides, and the
  three printed shapes are 701.57a, 702.85a, 702.75a).
- **No `RuleRef` attribute on the `Placement` enum** — the attribute's usage was not verified inside
  the box, so the citation lives in the doc comment. Worth adding if `RuleRef` already permits enums.

  `dotnet format --verify-no-changes` on all three projects. **Whoever merges this must run both
  first.** All twelve touched files were normalised to CRLF with the node one-liner after the last
  edit.
- **No card ids in the table** — V14 left the same debt and it is still open. Each gap was found by
  the printed phrase in the brief; the box went to the records. The **ids for both V14's nine and
  these eleven** should be attached by searching `cards/` for the printed phrase, never trusting a
  handed-over id, before the redo.
- **No lint for gaps 3, 4, 7 or 8.** `DamageCantBePrevented` beside a `DealDamage.CantBePrevented`
  rider is the only contradiction those four can express and is L044; a public reveal beside a
  private look, a `Distinct` written where a filter belonged, and a placement of `Bottom` where
  `BottomRandomOrder` was meant are all indistinguishable from the correct card by the linter. The
  one-spelling lines carry them instead.
- **The first `DamageCantBePrevented` lint I wrote could not fire.** It refused the record beside a
  `PreventDamage` in one ability — but `StaticAbility` holds exactly one `ContinuousEffect` and no
  `Effect` record carries one, so no ability can hold both. It was replaced by the `DealDamage`
  rider check, which is constructible and is tested. **If a composite `ContinuousEffect` is ever
  added, the original check becomes worth having.**
- **`DamagePrevented.ThisWay` has no lint tying it to a prevention this object actually applies.**
  The prevention can be on a different face, in a `RegenerationShield`, or from a shield counter
  (CR 122.1c), so a producer/consumer pairing would have too many arms to be right in this box.
- **`SpellCast.Nth` is an `int?`, not an `Amount`.** No corpus card counts a variable Nth spell; if
  one appears it is a shape change to an existing record and moves `IrVersion`.
