# V2 — creature types from the rules

The generated list, the layer-4 arms and the query's readers landed as briefed. Three things
V2 does not own, in the order they cost something.

## 1. `MtgEngine.Api` does not build on the integration branch, so `MtgEngine.Cards.Tests` cannot run

Blocking, and not mine to fix. `4e97e3f` ("Seams after wave 2") gave `Game.Wave1` an optional
parameter — `public static Subsystems Wave1(Func<string, bool>? enforced = null)` — and a method
group with an optional parameter no longer converts to `Func<Subsystems>`. Two call sites in the
API were left behind:

```
MtgEngine.Api/Program.cs(136,5): error CS1503: Argument 4: cannot convert from 'method group'
    to 'System.Func<MtgEngine.Rules.Engine.Subsystems>?'
MtgEngine.Api/Services/GameSessionService.cs(56,23): error CS0019: Operator '??' cannot be
    applied to operands of type 'Func<Subsystems>' and 'method group'
```

Both are one character each — `() => Subsystems.Wave1()` in place of `Subsystems.Wave1`. It
matters here because `tests/MtgEngine.Cards.Tests` project-references `MtgEngine.Api` (for
`ComprehensiveRulesParser`, the keyword-agreement test), so **no test in that project can build
or run** while this stands, mine included.

`CreatureTypeTests` in that project is therefore verified indirectly: it was compiled and run
against `MtgEngine.Cards` in a scratch project under `.agent/tmp` (same `Directory.Build.props`,
same analyzers, same xunit) — 6 tests, all green, 0 warnings. It has not been run through
`tests/MtgEngine.Cards.Tests` itself, and cannot be until the API compiles.

## 2. `StateBasedActions.Permanents.cs` has a second `HasSubtype` that does not read the flag

`MtgEngine.Rules/Sba/StateBasedActions.Permanents.cs:164` compares the subtype list directly.
Every subtype it asks about today is an Aura, an Equipment or a Saga (CR 704.5m, 704.5n,
704.5s) — none of them a creature type — so the answer is right today and the file is E5's, not
V2's. If an SBA ever asks about a creature type it must go through the flag: an object that is
every creature type (CR 205.3d) has it without it being in the list.

## 3. `ViewProjector` drops "every creature type" from the per-player view

`MtgEngine.Rules/Views/ViewProjector.cs:123` sends `chars.Subtypes` as it is, so a client sees a
changeling's printed subtypes and cannot tell it is every creature type. Either the flag travels
on the view record, or the projector expands it into the list at the boundary (the one place
where a list of CR 205.3m names is harmless, because nothing downstream reasons with it). E14's
call.

## Not a request

`Characteristics.EveryCreatureType` was already on the record with a default, per DECISIONS.md
row "V1 | `Layers` applies `AddTypes.AllCreatureTypes` | Wave 3 (V2)", so no seam changed. The
creature-type list is generated into `MtgEngine.Cards/Generated/CreatureTypes.g.cs` from CR
205.3m by `tools/gen-vocabulary.js`, beside the keyword enums; no creature type is written in
`MtgEngine.Rules`, and a new set is a rules-file swap plus a generator run.
