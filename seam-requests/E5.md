# E5 seam requests

## 1. CR 704.5h needs "was dealt damage by a source with deathtouch" in the state

**What I need.** A stored flag on `GameObject`:

```csharp
/// <summary>Set when a source with deathtouch dealt this permanent damage, CR 702.2b; cleared by the next state-based action check, CR 704.5h.</summary>
public bool DealtDeathtouchDamage { get; init; }
```

and a way for the SBA check to clear it — either a field on `ObjectChanged`
(`bool? DealtDeathtouchDamage`) or a dedicated event, because 704.5h is scoped to damage
dealt *since the last time state-based actions were checked* and the flag has to be reset
once the check has read it.

**Why.** 704.5h destroys a creature with toughness greater than 0 that was dealt damage by a
source with deathtouch, whatever the amount. `DamageDealt` carries `Source`, but the state
only keeps the total in `GameObject.Damage`; once the event has folded, nothing in
`GameState` remembers which source dealt it, so the deathtouch arm of 704.5 cannot be
computed from the state the seam hands me (`IStateBasedActions.Check(GameState)`).

Deriving it is not available either: `ICharacteristics.Of` answers for the *damaged*
creature, not for whatever damaged it, and reconstructing the source from
`state.Combat` would only cover combat damage and would be wrong the moment a
deathtouch source deals noncombat damage.

**Who else it touches.** Whoever writes `DamageDealt` (E4 for combat, E9/E3 for spells) sets
the flag when `ICharacteristics.Of(source).Has(KeywordKind.Deathtouch)`. Everything else in
704.5 lands without it, so this is the only arm of my brief I have left out; the rest of
`Sba/` is written and tested.

## 2. Notes, not requests

- **`PlayerState.DrewFromEmptyLibrary` is never cleared.** 704.5b is also "since the last
  time state-based actions were checked". Today the flag is set by
  `DrawFromEmptyLibraryAttempted` and there is no event that unsets it, so once it is true a
  player loses on every subsequent check. That is harmless while the loss stands, and only
  becomes visible when a replacement effect (E8, wave 2) replaces the game loss — at that
  point the same event/field question as above applies. Not blocking me.
- **An Aura cannot be attached to a player.** `GameObject.AttachedTo` is an `ObjectId?`, so
  "enchant player" has nowhere to record its host and 704.5m reads such an Aura as attached to
  nothing and buries it. That is wrong but harmless today, because no card in the free slice
  enchants a player; it becomes a real defect the first time one is translated, and the fix is
  a `PlayerId? AttachedToPlayer` (or an `AttachedTarget` union) on `GameObject` plus the
  corresponding field on `ObjectChanged`. Filed as a note rather than a request because it
  blocks nothing in wave 1.
- **The format is not in `GameState`.** `GameSetup.Format` and `GameStarted.Format` exist but
  the fold drops them, so CR 903.10a cannot ask "is this a Commander game". I gate the
  21-damage check on `PlayerState.CommanderDamage` having any entry instead: only
  `DamageDealt` with `FromCommander: true` populates it, which only happens in a game with
  commanders. That works, so no change requested — but if a non-Commander format ever needs
  to suppress it, `GameState` will need the format.
