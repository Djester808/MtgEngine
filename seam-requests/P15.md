# P15 — seam requests

## 1. "Enters prepared" cancels the entry, so the stack never empties (engine, not the generator)

Verify reports `The stack never emptied` for the smoke scenario of
`cards/58b0c737-0a84-4f9a-b3b7-300c5de43874.json`. It is not the generated scenario and it is
not `Prepare` itself. The reading is the same shape every "enters tapped" card uses:

```json
{"kind":"ReplacementAbility",
 "instead":{"kind":"WouldEnterBattlefield","what":{"also":{"kind":"IsThisObject"}}},
 "with":{"kind":"Prepare","what":{"kind":"Self"}},"selfOnly":true}
```

`ReplacementSystem.Perform` (`MtgEngine.Rules/Replacement/ReplacementSystem.Applying.cs`) has
five arms that *modify* an entry — `EntersTapped`, `EntersWithCounters`, `EntersAs`,
`PreventThatDamage`, `ModifyAmount` — and its `default` arm is CR 614.1a: **the event does not
happen** and the effect runs instead. `Prepare` has no arm, so it falls to the default: the
creature never enters the battlefield, the spell that was resolving has nowhere to put its
permanent, and the stack keeps the entry. Every card that "enters prepared" fails this way, and
so would any other entry modification spelled as a verb rather than as one of the five.

**Asked for** (`MtgEngine.Rules/Replacement/**`, an E-series owner, not P15): a sixth modifying
arm, `case Cards.Prepare: return new Applied(Entering(current, obj => Designated(obj,
Designations.Prepared, true)), state, [])`, matching `EntersTapped` exactly, and the same for
`Unprepare` if a card ever spells it. The interpreter already writes the designation
(`EffectInterpreter.Backlog.cs:63`), so only the entry road is missing.

The alternative — a vocabulary `EntersPrepared` beside `EntersTapped` — is a second spelling of
one meaning and would need every reading re-translated; the arm is the smaller change.

**Not run through a game.** This is reasoned from the two files above and matches the reported
symptom exactly; the arm's owner should reproduce it with the card's own smoke scenario before
landing, and the assertion belongs in the Rules tests, not in `ScenarioRunnerTests`.

## 2. Two folds the re-translation asks for that P15 decided **not** to make

Both are recorded here so the next pass does not re-open them without the reasons.

**`Target` with a `key` read back by `Remembered`, against the same target read again.** The
prompt's rule (`MtgEngine.Cards.Pipeline/VocabularyReference.cs:61`) makes "reads the target
again" the canonical form and remembering the exception, so the fold direction would be
`Target(key) + Remembered(key)` → `Target` + `ThisSpellsTargets`. It is **not** implemented, for
three reasons, and the third is decisive:

1. `ThisSpellsTargets` is *all* of the spell's targets and exists only on a spell ability, so the
   fold needs an ancestor test (a SpellAbility) and a "this spell has exactly one target" test
   that the node-local pass cannot see today.
2. The fold is only safe while the object cannot have changed zones between the two reads.
3. **Every disputed card in this family moves the object**: Swords to Plowshares exiles it,
   Beast Within destroys it, Erode and Demolition Field destroy a land, Reanimate moves the card.
   Under the rule's own condition none of the five would fold, so the rule would be code that
   changes no card and risks the one card it did fire on.

If a later round wants it, the honest version is a prompt change — say which of the two to write
when the object stays put — not a canonical rewrite.

**`Compare(CountOf(A), Gt, CountOf(B))` against `Controls(who, what, count)`** (Land Tax's first
difference). Not folded: `Controls` names the player whose objects are counted in its own `Who`,
and `Compare` names them inside the left filter's `controlledBy`. Folding `Controls` into
`Compare` means merging `Who` into a filter that may already carry a `controlledBy`, and folding
the other way means deciding which half of a `Compare` is "the controller" — neither is a
mechanical rewrite, and both would be the first rule in `Canonical` that has to *understand* a
condition rather than restate it. Two readings that chose different records here have made a
real choice, and the report's own note (`Canonical.cs`: "Compare against Controls … a real
disagreement") already ruled it once. Left disputed.
