# E15 — faces and layouts: the calls other folders must make

`MtgEngine.Rules/Faces` is pure: no state, no events, no seam interface. Nothing in it runs
unless another subsystem calls it, and today nothing does. Each request below is one call in
someone else's file. None of them needs a change to `Engine/Seams.cs`, `Events/GameEvent.cs`
or `State/*`, except the two marked **state** at the end.

## 1. Layers — `Characteristics/Layers.cs` (E7)

`Printed` reads `obj.Face`, which is `Definition.Faces[FaceIndex]` unconditionally. That is
wrong in every zone the rules hide a face in: a transformed permanent that is bounced to hand
still reads its back face (CR 712.8a), a flip card in a graveyard reads its flipped face
(CR 710.2), and an adventurer in exile reads its Adventure half (CR 715.4).

Replace `var face = obj.Face;` with:

```csharp
var face = obj.FaceDown
    ? FaceRules.FaceDown
    : obj.Definition.Faces[FaceRules.ActiveFace(obj.Definition, obj.Zone.Zone, obj.FaceIndex)];
```

`FaceRules.FaceDown` is the CR 708.2a face — 2/2 creature, no name, no subtypes, no text, no
mana cost — so the hand-written face-down block in `Printed` (lines 114–128) becomes the
`Face` above and the special case goes away. One rule, one place.

Split cards are the one layout whose characteristics are two faces at once (CR 709.4): in
every zone but the stack, a split card's types, abilities and mana cost are the halves
combined. `FaceRules.ActiveFaces` returns both indexes and `FaceRules.IsCombined` says when to
fold; `ActiveFace` returns the first half so a caller that cannot fold still reads a real
face. Folding two faces into one `Draft` is layer work, not face work, so it is E7's, and
until it is done a split card in hand reports its left half. I have not changed `Layers.cs`.

## 2. Casting — `Casting/CastingSystem.cs` (E3)

`Cast` currently refuses any face but the stored one:

```csharp
if (command.FaceIndex != card.FaceIndex)
    throw new RefusedException("Casting another face of a card is not supported yet.", "712");
```

Replace it with the choice CR 601.3b gives the player:

```csharp
var options = FaceRules.CastableFaces(card.Definition, card.Zone.Zone);
var chosen = options.FirstOrDefault(o => o.FaceIndex == command.FaceIndex)
    ?? throw new RefusedException("That face cannot be cast from there.", "601.3b");
if (chosen.IsLandFace)
    throw new RefusedException("A land face is played, not cast.", "712.12");
```

and then read the spell's characteristics from `chosen.FaceIndex`, not from `card.FaceIndex`:
`StackZone.MoveSpellToStack` must put the object on the stack with `FaceIndex = chosen.FaceIndex`
(CR 712.11c, 709.3a, 715.3a — only the face being cast is evaluated and only it is put on the
stack). `characteristics.Of` then returns the right face on its own, because the layer change
above keys on the zone.

Three consequences E3 owns:

- **CR 712.12** — a modal double-faced card's land face is *played*. `PlayLand` needs the same
  `CastableFaces` lookup and must accept a `FaceIndex` on the command.
- **CR 715.3d** — an Adventure spell is exiled as it resolves and its controller may play it
  later. `FaceRules.ResolvesTo(definition, faceIndex)` returns `(Zone, MayCastLater, Rule)`;
  the resolution path in `ResolveTop` should send the card there instead of the graveyard.
  CR 720.3d does the same for an Omen, into the library.
- **CR 709.3b / 715.3b** — while a chosen half is on the stack the other half's characteristics
  do not exist. That falls out of the stack object carrying `chosen.FaceIndex`.

## 3. The interpreter's verbs (E9, E10/E11)

Four keyword actions are `Faces` calls, each returning what happened and the rule that says so,
never mutating anything:

| Verb | Call | Returns |
|---|---|---|
| transform, CR 701.27 | `FaceRules.Transform(definition, faceIndex)` | `TurnedFace(Turned, FaceIndex, Rule)` |
| convert, CR 701.28 | `FaceRules.Convert(definition, faceIndex)` | the same; 701.28a makes it the same action |
| flip, CR 710 | `FaceRules.Flip(definition, faceIndex)` | `TurnedFace`, one-way per 710.4 |
| meld, CR 701.42 | `FaceRules.Meld(first, second)` | `Melded(Success, Combined, FaceIndex, Rule)` |

`Turned == false` means CR 701.27c/d, 712.4c, 712.10 or 710.4 said nothing happens, and the
interpreter emits no event. When it is true the interpreter needs an event to fold — see the
state request below.

Copies (CR 707) are `Faces/Copies.cs`:

- `CopyRules.CopyOf(source)` reads an object's copiable values — the definition, the face that
  is up, and face-down status; CR 707.2 leaves status, counters and damage out.
- `CopyRules.Become(target, values)` is a permanent becoming a copy: it keeps its own counters,
  damage and status, which were never copied.
- `CopyRules.NewCopy(values, id, owner, controller, zone, timestamp)` is the token that is a
  copy, and the copy of a spell put on the stack (CR 707.10): a fresh object with the copiable
  values and nothing else.

`ZoneSystem.CreateToken` builds a token from a `TokenSpec`. A token that copies a permanent has
no `TokenSpec` — it has a `CopiableValues`. E1's `CreateToken` should gain an overload taking
`CopiableValues`, or E9 should call `CopyRules.NewCopy` and hand E1 the finished object. I have
not touched `Zones/`.

## 4. Two state requests, for the coordinator

**(a) `ObjectTurnedOver` event.** `Events/GameEvent.cs` has no event for a permanent changing
which face is up. `ObjectChanged` carries no `FaceIndex`. Transform, convert and flip all need
one event so the log replays and CR 701.27e's "transforms into" triggers have something to
match:

```csharp
public sealed record ObjectTurnedOver(ObjectId Object, int FaceIndex, TurnKind Kind) : GameEvent;
public enum TurnKind { Transform, Convert, Flip, TurnedFaceUp, TurnedFaceDown }
```

The kinds are one event rather than four because CR 701.27b and 701.28b turn on telling them
apart, not on their being separate events, and CR 701.27e explicitly matches both transform and
convert. Until this exists the verbs above compute the new face and nobody can record it.

**(b) A melded permanent is two cards.** `GameObject` holds one `CardDefinition`. CR 701.42a's
melded permanent is a single object represented by two cards, and CR 712.8g computes its mana
value from the sum of the two front faces. `FaceRules.Meld` returns which definition and face
the combined permanent reads, which is enough to put the right characteristics on the
battlefield, but not enough to unmeld it when it leaves (CR 712.4b) or to compute that mana
value. A `GameObject.Components` — an `ImmutableList<ObjectId>` or a second definition — is the
smallest thing that closes it. Not needed before a meld card is translated; filed so the shape
is decided before it is.

## Not done, and why

- Folding a split card's two halves into one set of characteristics: layer work (§1).
- Mana value of a transformed permanent from its front face's mana cost, CR 712.8e: mana value
  is not on `Characteristics` yet; it belongs with whoever adds it.
- `Layout.Leveler`, `Class`, `Saga`, `Mutate`, `Prototype`, `Battle`, `Case`: single-faced, so
  `ActiveFaces` returns the front face and the layouts' own rules (CR 711, 716, 714, 730, 718,
  719) are not face selection.
